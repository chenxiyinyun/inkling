# 《信逢-Inkling 全年龄安全体系与未成年人保护》

> 版本：v1.0（设计阶段）· 日期：2026-06-14 · 适用范围：MVP 强制项
> 适用法域：海外/港台（不走国内备案）。核心法规：GDPR / GDPR-K（欧盟）、COPPA + 2025 修订案（美国）、UK Online Safety Act（英国）、香港 PDPO、台湾《個人資料保護法》。
> **设计总原则（写入产品宪法）**：在多法域差异前，**一律按"最严标准"实现**（design for the most protective standard）。未成年人保护不是功能，是准入前置门（gate-before-collection）。

---

## 0. 总览：为什么这是 MVP 的"红线项"

因为产品同时选择了 **全年龄（含未成年人）+ 慢社交书信（陌生人 1:1 私密通信）+ 海外/港台**，三者叠加把本产品直接推入全球监管最敏感的象限：**面向儿童的、能让陌生成年人与未成年人 1:1 私密接触的服务**。

这正是近年天价处罚的高发区。可作为风险锚点的真实判例（已核实）：

| 案例 | 年份 | 罚则 | 核心指控（与本产品强相关） |
|---|---|---|---|
| Epic Games / Fortnite | 2022 | COPPA 罚 2.75 亿美元，合计 5.2 亿美元 | **将未成年人与陌生成年人实时配对**、默认开放通信、未取得家长同意收集 <13 数据 |
| Meta（新墨西哥州陪审团） | 2026-03 | 民事罚 3.75 亿美元（首例州诉陪审团裁决） | 成瘾设计、暴露未成年人于不当内容 |
| TikTok / Musical.ly | 2019 / 2024 进行中 | 2019 罚 570 万；2024 新诉进行 | 明知允许儿童注册并收集数据 |
| HoYoverse / Genshin | 2025 | 拟和解 2000 万美元 | 收集 <13 数据、向 <16 售卖盲盒 |

**关键监管事实（已核实，写入合规台账）：**

- **COPPA**：管 <13；单次违规民事罚 **上限 USD 53,088**；州 AG 可独立起诉。**2025 修订案**新增：数据留存/删除、第三方共享（广告/分析/**AI 训练**）须**单独的可验证家长同意（separate VPC）**、混合受众站点的年龄筛查义务。**AI 训练用儿童数据须单独家长同意，合规截止日 2026-04-22**。
- **GDPR-K**：成员国数字同意年龄在 **13–16 之间浮动**（德国 16，多数 16，部分 13）。违规上限 **EUR 2000 万或全球营收 4%**。
- **UK Online Safety Act**（2025-07-25 全面生效）：要求 **"highly effective age assurance（高效年龄保障）"**，**自声明明确不达标**（Ofcom 已表态）；罚则上限 **GBP 1800 万或全球营收 10%**，**高管可负刑责**。
- **香港 PDPO / 台湾個資法**：以告知同意、目的限制、数据最小化为核心；台湾对未成年人个资处理需法定代理人同意。

**结论**：本产品的未成年人保护必须做到三件事——**(a) 准入前可证明的年龄分流；(b) 未成年人与陌生成年人的强隔离；(c) grooming/线下约见/索取私密信息的零容忍拦截与留证**。下文给出可落地规则、阈值与处置阶梯。

## 1. 年龄门控与验证（Age Gating & Age Assurance）

### 1.1 年龄分级（三档 + 一个"不确定"态）

| 档位 | 范围 | 准入态 | 核心限制摘要 |
|---|---|---|---|
| **U13（儿童）** | < 13 | **MVP 默认：不直接开放**；如开放则**强制 VPC（可验证家长同意）** | 触发 COPPA / GDPR-K 最严义务。MVP 推荐：**对 <13 直接拒绝注册**（最低风险路径），引导"家长陪同/等待长大"。若产品决意开放，须先落地完整 VPC 链路（见 1.4）。 |
| **T1317（青少年）** | 13–17 | **允许，强制进入"守护模式"**（默认开、不可由本人完全关闭） | 仅同龄池匹配、关精确地理、时段限制、家长可见层（按法域）、更严内容阈值（见 §2）。GDPR-K 法域中 13–15/16 仍可能需家长同意——按用户**声明所在地法域**动态判定（见 1.3）。 |
| **A18（成年）** | ≥ 18 | 正常准入 | 仍受通用安全约束（§4）；女性账号默认更严守护（§4.4）。 |
| **UNK（年龄不确定）** | 验证失败/拒绝验证/信号矛盾 | **按 T1317 待遇兜底**（保守降级） | 在完成升级验证前，**一律享受未成年人保护**，不得进入成年人开放池。 |

> **设计铁律 1：保守兜底（fail-safe to minor）。** 任何无法可靠确认为成年的账号，一律按未成年人对待。宁可错把成年人当未成年人保护，不可反向。

### 1.2 注册年龄声明（neutral age screen）

- **采用中性年龄门（neutral age-gate）**：注册时要求输入**出生日期（年月）**，而非"你满 18 吗？是/否"。后者诱导谎报，且 FTC 已批评其无效。
- **中性呈现**：不在年龄输入页暗示"满 18 才能用全部功能"等诱导文案（避免被认定为"诱导谎报年龄"）。
- **防重置**：同一设备/账号短时间内反复改写出生日期，记为**年龄信号矛盾**，置 UNK 并触发升级验证。出生日期一经设定，**修改需走人工申诉 + 重新年龄保障**，不可前端自助改。
- **存储最小化**：仅存出生**年月**（或直接存"档位 + 验证等级"），不必存精确日期；港台/GDPR 数据最小化要求。

### 1.3 法域判定（决定走 COPPA / GDPR-K / OSA / PDPO 哪一套）

输入信号优先级：①注册时用户声明的**居住地/国家**（必填，下拉）→ ②设备/IP 推断地（仅用于冲突检测，不落库原始 IP）→ ③应用商店区域。

- 居住地与推断地**冲突**时：取**更严**的一套义务（例：声明香港但 IP 在德国 → 适用 GDPR-K 16 岁同意线）。
- 维护一张**法域→数字同意年龄/家长同意要求/守护强度**映射表（配置化，可随法规更新热更，无需发版）。

| 法域 | 强制家长同意年龄线 | 守护备注 |
|---|---|---|
| 美国 | < 13（COPPA） | 多州另有 13–16 父母同意/年龄验证要求，按州细化 |
| 欧盟（GDPR-K） | 成员国 13–16（默认按 **16** 兜底） | DSA 禁止对未成年人基于画像的广告 |
| 英国（OSA） | < 18 全部受保护 | 须"高效年龄保障"，自声明不达标 |
| 香港 PDPO | 无单一法定线，按"明确同意"+最小化 | MVP 取 18 为成年线，<18 入守护 |
| 台湾 個資法 | 未成年须法定代理人同意 | <18 入守护，敏感操作需家长同意层 |

### 1.4 Age Assurance 方法选型与可靠性权衡

监管已明确：**自声明对"高风险接触场景"不达标**（UK Ofcom、US FTC 均表态）。本产品属高风险（陌生人 1:1 私密通信），需**分级年龄保障**：低风险动作可宽松，高风险动作（与陌生成年人接触、解除守护、跨档匹配）必须升级。

| 方法 | 可靠性 | 隐私/摩擦 | 成本 | 本产品用法 |
|---|---|---|---|---|
| **自声明（出生日期）** | 低 | 极低摩擦 | 0 | 注册基线档位判定；**不可作为解除守护或跨档接触的唯一依据** |
| **AI 面部年龄估计**（如 Yoti Facial Age Estimation） | 中-高（FTC 正评估其作为 VPC 方法） | 中（需活体自拍，**估值即弃、不存原图**） | 中 | T1317↔A18 边界争议时的**升级验证**；可作为"我是成年人"的证明路径 |
| **信用卡校验（小额授权/退款）** | 中（仅证明持卡，不等于成年本人） | 中 | 低-中 | VPC 备选之一；成年验证的辅助信号 |
| **第三方身份/年龄验证（Reusable Digital ID / 政府 ID）** | 高 | 高摩擦 | 高 | 仅用于**最高风险动作**（如开放精确地理、申诉解除守护误判） |
| **VPC 链路（可验证家长同意）** | —（流程，非单点） | 高 | 高 | <13（若开放）与 GDPR-K 法域下 13–15/16 强制（见下） |

**VPC（Verifiable Parental Consent）链路设计（COPPA / GDPR-K 共用骨架）：**

1. **未成年人触发**：注册声明年龄落入"需家长同意"区间（<13 或法域内 <数字同意年龄）。
2. **收集家长联系方式**：仅向未成年人收取**家长邮箱**（数据最小化，先不收家长更多信息）。
3. **家长侧验证（择强）**：
   - 信用卡/借记卡小额授权（可立即退款）——COPPA 公认 VPC 方法之一；
   - 政府 ID / 第三方年龄验证；
   - 视频通话/签字表单回传（"print-and-send"/电子签）；
   - （前瞻）面部年龄估计待 FTC 正式批准后纳入。
4. **同意范围明确化（separate consent）**：家长须就以下**分别勾选**：① 账号创建与基础书信；② 任何第三方数据共享（广告/分析）——**MVP 对未成年人默认全部关闭，无需此项**；③ **绝不**将未成年人数据用于 AI 训练（合规截止 2026-04-22；MVP 直接承诺"未成年人数据永不入训练集"）。
5. **可撤回**：家长可随时撤回同意 → 触发账号冻结 + 数据删除流程（COPPA 删除权 / GDPR 删除权）。
6. **留痕**：每次年龄保障/同意事件**带时间戳、方法、结果**写入**审计日志**（监管要求"auditable, logged, timestamped, available on request"）。

> **设计铁律 2：gate-before-collection。** 年龄分流必须在任何业务数据收集与匹配之前完成。守护模式相关设置在账号激活时即就位，不得"先放进池子再补"。

## 2. "守护模式"完整规则（Guardian Mode）

**默认对象**：全部 T1317 与 UNK 账号。**不可由未成年人本人完全关闭**；仅可在**通过更高等级年龄保障证明为成年**后由系统降级（见 1.4），或由家长在其可见层内调整（仅能调严，不能调松到低于法定底线）。

### 2.1 匹配隔离（核心：防止陌生成年人接触）

| 规则 | 取值 | 说明 |
|---|---|---|
| **同龄池隔离** | **强制**：T1317 仅与 T1317 互相匹配 | 未成年人**不得**被投递给陌生成年人，**也不得**打捞到陌生成年人的信。这是对标 Epic/Fortnite 判例的核心整改点（"将未成年人与陌生成年人实时配对"是被罚根因）。 |
| **年龄带宽** | T1317 内进一步收窄（如 ±2–3 岁优先） | 13 岁不与 17 岁优先匹配，降低同池内年龄差风险。 |
| **UNK 处理** | UNK 入"待定隔离池"，**只与已确认成年人之外**的对象匹配；优先引导完成年龄保障 | 在确认成年前不进成年开放池。 |
| **成年人侧** | A18 默认**看不到、捞不到**任何 T1317/UNK 信件 | 双向隔离，不依赖未成年人自我保护。 |

> **MVP 实现**：在匹配召回阶段加**硬过滤（hard filter）**：候选集生成 SQL/向量召回前，先按 `account_tier` 切分两个不相交的池。隔离是**召回前置过滤**，不是排序降权——必须是"绝对不可能配上"，而非"概率低"。

### 2.2 零容忍语义：线下约见 / 索取照片 / 索取位置

对**所有进入或离开未成年人账号**的信件内容（投递、打捞预览、拆封、回信），机器审核**额外加载"未成年人零容忍语义集"**（§4.3 审核流水线的高优先策略）。命中即**拦截 + 留证 + 升级**（不进低危递送窗，见 §3）：

**零容忍语义类别（多语种）：**

1. **线下约见/见面**："我们见个面吧 / 来我家 / 你住哪我去找你 / let's meet / 線下見 / 約出來"——含时间地点暗示尤甚。
2. **索取真人照片**："发张你的照片 / 自拍 / 你长什么样 / send a pic / 露脸 / 私房照"——索取**私密/裸露**照片为**最高危（直接进入 grooming/CSAM 风险线，见 §3）**。
3. **索取精确位置**："你具体在哪 / 定位发我 / 哪个学校 / 哪个小区 / share your location"。
4. **索取其他联系方式**（脱离平台）："加我微信/WhatsApp/IG / 我们去别的地方聊 / 这里不安全去别处"——**孤立性话术**，grooming 高信号。
5. **索取家庭/独处信息**："你爸妈在吗 / 你一个人吗 / 几点没人管你"。

### 2.3 地理与精确度

- **关闭精确地理**：T1317/UNK 账号**禁用** GeoHash5（±2.4km）参与匹配，**降级为城市/地区级**（GeoHash3 或行政区，±数十 km），仅用于"递送速度粗档"，**不用于"就近匹配"**。
- 原始经纬度本就**内存即弃不落库**（产品既定）；对未成年人**额外**关闭任何"附近的人"语义。
- 未成年人信件内容中**出现的**精确地址/学校名/门牌，由审核流水线**自动打码/拦截**（既保护本人，也阻断对方索取）。

### 2.4 时段限制（curfew）

- 默认**宵禁**：本地时间 **23:00–06:00** 暂停未成年人账号的新投递/打捞/拆封交互（对标 NY SAFE for Kids "午夜至 6am 禁推送"、Vermont 禁深夜推送的监管方向）。
- 宵禁期**不推送任何通知**给未成年人账号。
- 家长可见层可**进一步收紧**宵禁时段，不可放宽到低于默认。

### 2.5 家长可见 / 管理范围（按法域分层）

> 平衡点：满足监管"家长管理"要求，但**不破坏书信隐私核心**（产品价值=真诚私密）。原则——**家长能管"框架与安全"，不能读"信件内容"**（除非法域强制 + 经申诉/危机流程）。

| 家长可见/可管 | T1317 一般法域 | GDPR-K 需同意法域 / <13 |
|---|---|---|
| 账号存在与状态（活跃/冻结） | ✓ | ✓ |
| 安全设置（守护强度、宵禁、隐身） | 可见，可调严 | 可见可管 |
| 配额使用（投/捞/拆次数） | ✓ | ✓ |
| 收到的**举报/处置记录**（涉及本账号的安全事件摘要） | ✓（脱敏） | ✓ |
| **信件正文内容** | **默认不可读**（保护隐私） | 经 VPC 框架，家长在法域强制下可申请；**危机/grooming 命中时系统主动告知**（见 §3、§6） |
| 撤回同意 / 删除账号 | ——（按法域） | ✓（COPPA/GDPR 删除权） |
| 家长账号绑定 | 通过 VPC 邮箱建立 | 通过 VPC 强绑定 |

## 3. Grooming（诱导）专项行为模型

Grooming 的本质是**关系演化过程**，单封信往往"看着没问题"，必须做**跨信件、跨时间的行为序列建模**。这是与普通内容审核最大的区别。

### 3.1 识别信号（信号即特征，加权累积成"grooming 风险分"）

按权重分档（命中即累加，分数随时间窗衰减但留痕）：

| 信号类别 | 具体信号 | 权重 |
|---|---|---|
| **定向低龄（targeting）** | 成年人账号（A18）持续、定向地与多个未成年人/低龄信号账号通信；偏好滑杆/历史行为指向"找年轻对象" | 高 |
| **索取私密信息（elicitation）** | 索取真人照片（尤其私密/裸露=**最高**）、精确位置、学校、独处时间、家庭监管情况 | 私密照片=零容忍最高；其余高 |
| **孤立性话术（isolation）** | 引导脱离平台（"加我别的号""去别处聊""别告诉爸妈/这是我们的秘密"）、制造"只有我懂你"的排他依赖 | 高 |
| **礼物/利益诱导（gift/grooming bribe）** | 提出寄礼物、给钱、给会员/游戏点卡、承诺好处换取照片/见面/联系方式 | 高 |
| **关系加速（boundary erosion）** | 短期内迅速升温、过度赞美、性暗示渐进试探、推动私密话题 | 中-高 |
| **线下推进（meeting）** | 任何约见、问地址、提出来接送 | 零容忍最高 |
| **年龄不对称** | 双方年龄差大 + 上述任一 | 放大系数 |

### 3.2 风险分阈值与命中处置阶梯

设 grooming 风险分 `G`（0–100，跨信件累积，按账号对 + 单账号双维度统计）：

| 阶梯 | 触发 | 自动处置 | 人工/外部 |
|---|---|---|---|
| **L0 观察** | 单一中危信号 | 静默加权、加入观察名单、不打扰用户 | — |
| **L1 软干预** | G ≥ 30 或命中 1 个高危信号 | 向**未成年人侧**插入安全提示卡（"对方在索取你的照片/位置，这可能有风险，你可以举报/拉黑"）；该信件**不进低危递送窗，转人工队列** | T&S 队列 24h 内复核 |
| **L2 拦截+冻结接触** | G ≥ 60 或命中任一**零容忍**（私密照片/线下约见/脱平台孤立） | **立即拦截该信件不投递**；冻结该成年账号对未成年人的全部接触能力；保全证据 | T&S **优先**人工 ≤ 4h；触发家长告知（按法域 §2.5） |
| **L3 封禁+强制报告** | 确认 grooming / 索取或传播 CSAM / 实质线下推进 | **永久封禁**成年账号；冻结相关数据用于取证；未成年人账号转危机关怀流程 | **强制报告**（见 3.4）+ 留证移交执法/NCMEC/当地机构 |

> **CSAM 红线（绝对零容忍）**：任何疑似儿童性虐待材料（请求、暗示、传播）→ **立即 L3 + 强制报告**，跳过软干预阶梯。**严禁本平台主动留存 CSAM 影像本体**；按法域走"哈希比对 + 即时移交 NCMEC/执法 + 锁定证据元数据"的合规取证路径（影像本体的处置遵循当地法定流程，不得二次传播）。

### 3.3 强制报告（mandatory reporting）触发与对象

- **美国**：疑似 CSAM **依法须报告 NCMEC（CyberTipline）**；这是平台法定义务，非可选。
- **英国**：OSA 框架下向 Ofcom / NCA-CEOP 路径；高管对儿童安全义务负潜在刑责。
- **香港**：移交香港警务处（含 against child abuse 相关机构协作）。
- **台湾**：依《兒童及少年福利與權益保障法》/《兒少性剝削防制條例》，向主管机关/警方通报。
- 维护**法域→强制报告对象/路径/时限**配置表，由法务季度复核。

### 3.4 留证（evidence preservation）流程

1. **触发即冻结快照**：命中 L2/L3 时，对相关信件、账号元数据、时间戳、年龄保障记录、grooming 信号命中明细生成**不可篡改快照**（WORM/审计日志），与正常业务库隔离存储。
2. **保全范围**：内容文本、收发关系、配额/匹配上下文、IP 推断地（仅在取证场景内、按法域许可范围）。**注意**：常规不落库的原始经纬度仍不落库；取证不得突破"原始经纬度不落库"承诺，只用已留痕的粗档地理。
3. **链路完整性**：操作者、操作时间、处置理由全程审计（chain of custody）。
4. **留存期限**：按法域强制报告/诉讼时效设定最短保全期；到期且无诉讼/调查则按删除策略清理。
5. **数据最小化兼容**：取证留存是"合法目的下的例外"，须在隐私政策中明确披露其法律依据（COPPA/PDPO/個資法的法定义务豁免）。

## 4. 通用安全（全年龄）

### 4.1 闭环：举报 → 拉黑 → 隐身 → 处置 → 申诉

```
[举报] 一键举报（信件内/笔友信匣内/打捞预览内均可）
   │  分类：骚扰 / 性内容 / 联系方式索取 / 诈骗·金钱 / 自残·危机 / 涉未成年 / 其他
   ▼
[即时自保] 举报同时可一键【拉黑】+【隐身】
   - 拉黑：对方永不再与我匹配/投递/打捞到我；历史往来对其只读冻结
   - 隐身：我暂时退出漂流海，不被打捞、不被匹配（女性/受扰用户高频用）
   ▼
[分诊] 机器分级：高危→秒级拦截+人工优先队列；中危→人工队列；低危→批量
   ▼
[处置阶梯]（见 4.2）
   ▼
[通知] 举报人收到"已处理"状态（永不显示对被举报方的细节）；被处置方收到处置通知+申诉入口
   ▼
[申诉] 被处置方可申诉 → 独立复核（非原处置人）→ 维持/撤销/降级 → 记录
```

> **永不显示"已读"**（产品既定）在安全侧的含义：举报、拉黑、隐身对被作用方**不暴露触发者身份与时点**，避免报复。

### 4.2 处置阶梯（对违规账号）

| 等级 | 适用 | 处置 |
|---|---|---|
| P0 提示 | 轻微/疑似 | 软提示、内容不投递、教育引导 |
| P1 限流 | 中危/多次轻微 | 降低配额、暂停打捞/投递、内容进人工 |
| P2 功能冻结 | 高危/累犯 | 冻结匹配与新接触能力，保留申诉 |
| P3 封禁 | 零容忍/确认 grooming/CSAM/诈骗团伙 | 永久封禁、留证、（涉未成年/CSAM）强制报告 |
| P4 移交 | 涉刑/涉未成年 | 移交执法/NCMEC/当地机构 |

### 4.3 内容审核流水线（多语种，海外必备）

**分层策略：机器秒级拦高危 / 低危藏进递送窗 / 多语种覆盖。**

```
信件提交（草稿→AI审核）
  │
  ├─ Stage 1 机器秒级（同步，阻断式）：高危类别
  │     性内容(成人/未成年) · 联系方式索取 · 骚扰/仇恨 · 自残/危机(E类) · 诈骗/金钱
  │     未成年人账号额外加载"零容忍语义集"(§2.2)
  │     命中高危 → 立即拦截，不进在途；危机类(E)走 §6；CSAM 走 §3 红线
  │
  ├─ Stage 2 机器异步(低危/灰度)：可疑但非高危
  │     处置 = "藏进递送窗"：让信件按正常在途延迟(车马/信鸽)走流程，
  │            利用递送时延窗口完成异步复核/人工抽检，不阻断体验，
  │            若期间判违规则在"到达漂流海前"撤回。
  │
  ├─ Stage 3 行为/关系层(跨信件)：grooming(§3) + 杀猪盘(§5) 序列模型
  │
  └─ Stage 4 人工队列：高危优先(≤4h)、中危(≤24h)、申诉复核(独立)
```

**多语种要求（海外/港台）：**
- 覆盖**繁体中文、英文**为 MVP 必选；按目标市场扩展（粤语口语、日韩、欧洲主要语言为演进项）。
- 高危分类器须**多语种训练/评测**，对"中英混写、繁简混写、注音/拼音、谐音、emoji 替代"鲁棒。
- 未成年人零容忍语义集**逐语种维护词表 + 语义模型**双轨。

### 4.4 女性安全（默认更严守护）

- **分发保护**：女性账号**默认隐身阈值更低**、被打捞频次有上限保护，避免被高频骚扰；可一键"仅接受同性/降低被投递曝光"。
- **默认更严**：女性账号默认开启"联系方式索取自动提醒""精确地理不参与匹配（与未成年同策略可选）"。
- **反报复**：拉黑/隐身/举报对对方完全不可见（呼应"永不显示已读"）。
- **快速通道**：女性安全相关举报（性骚扰、跟踪、索取私密照片）进**高危人工优先队列**。
- 注：以上为**默认**，用户可在知情下调整，但调整方向只能**更安全或维持**，不提供"关闭全部保护"的一键项。

### 4.5 联系方式检测的多语言对抗

索取/留下脱平台联系方式既是骚扰/诈骗信号，也是未成年人 grooming 的孤立话术，需专门对抗化检测：

- **目标实体**：微信/WeChat、WhatsApp、Telegram、IG、LINE、Discord、QQ、手机号、邮箱、各类 handle。
- **对抗变体覆盖**：
  - 谐音/拆字（"微 信""V X""薇芯""V:""加我企鹅"）；
  - 全角/特殊符号插入（`w·e·c·h·a·t`）；
  - emoji/图形替代（用🐧指 QQ、用绿色图标暗示微信、用✈指 Telegram）；
  - 数字汉字混写、火星文、注音、拼音首字母（"jwx"=加微信）；
  - 拆句跨信件给出（这封给前半段号码，下封给后半段）→ 由 §3 序列模型捕捉；
  - 图片/手写号码 → OCR + 视觉检测（演进项，MVP 先文本）。
- **处置**：成年人之间索取联系方式 → 中危提醒 + 限流；**涉及未成年人 → 零容忍（§2.2/§3）**。
- **多语种**：上述变体需在繁中、英文、（演进）粤语/日韩等分别建词表与规则。

## 5. 杀猪盘 / 情感诈骗的关系层风控

杀猪盘特征是**慢热建立信任 → 制造亲密/恋爱关系 → 跨多封信逐步引入金钱话术**。与 grooming 同属"关系演化序列建模"，需跨信件建模而非单封判定。

### 5.1 关系层信号（跨信件金钱话术建模）

| 阶段 | 信号 |
|---|---|
| 建立信任 | 高频深情通信、快速"恋爱"定调、身份故事（海外高管/军人/医生/独自在外） |
| 制造依赖 | 推动脱平台私聊（与 grooming 孤立话术重叠）、避免视频/见面找借口 |
| **引入金钱**（核心） | 提及投资/虚拟货币/"稳赚平台"、家人生病/海关扣押/急用钱、推荐"内部渠道""带你赚"、索要转账/代付/充值/礼品卡 |
| 收割 | 反复加码、制造紧迫、亏损后"再投就能回本" |

### 5.2 建模与处置

- **金钱话术分类器**（多语种）：识别"投资/转账/虚拟货币/紧急汇款/礼品卡/带单/回本"等语义簇。
- **关系轨迹评分**：单账号若呈"对多个对象批量深情 → 引入相同金钱剧本"的模式（脚本化、模板化语言复用），判为**疑似杀猪盘团伙**，权重大幅提升。
- **跨账号关联**：同一金钱剧本模板在多账号复现 → 团伙聚类，批量处置。
- **处置阶梯**：
  - 命中金钱话术（首次/低强度）→ 向收信方插入**反诈提示卡**（"对方在谈钱/投资，警惕情感诈骗"），信件转人工。
  - 命中"投资/转账/虚拟货币 + 紧迫性"或脚本复用 → **P2 冻结 + 人工优先**。
  - 确认团伙/脚本化 → **P3 封禁 + 关联清剿**，按法域可移交反诈/警方。
- **未成年人叠加**：未成年人收到任何金钱诱导 → 直接进 §3 grooming（礼物/利益诱导）零容忍线。

## 6. 自残 / 心理危机（E 类）的即时干预与海外资源对接

**原则**：危机内容**不当作"违规"惩罚发信人**，而是**关怀 + 即时干预 + 资源对接**。区分"自身处于危机"（关怀）与"鼓动/美化他人自残"（违规，按高危处置）。

### 6.1 即时干预流程

```
机器秒级识别 E 类(自残/自杀意念/危机)
  │
  ├─ 自身危机(求助/意念表达)：
  │   1) 不拦截发信人账号、不羞辱；该信件转人工关怀队列(高优先)
  │   2) 立即向发信人弹出【危机关怀层】：
  │        - 共情文案 + 按其法域展示本地 24h 危机热线(见 6.2)
  │        - "如有立即危险请拨打当地紧急号码(如 999/110/119/911)"
  │        - 引导联系信任的人
  │   3) 评估即时风险等级：
  │        - 高(明确计划/时间/手段) → 升级人工危机专员；
  │          未成年人 → 按法域触发家长/监护人告知与外部资源(§2.5)
  │        - 中/低 → 持续关怀 + 资源 + 后续关注
  │
  └─ 鼓动/美化/教唆他人自残(含未成年):
      → 高危违规，P2/P3 处置 + 留证(青少年自残社区是监管重点,如 Arkansas/UK OSA)
```

- **未成年人特殊处理**：未成年人 E 类危机命中 → 关怀层 + **按法域的监护人/外部干预**，并将"涉自残内容"排除在普通笔友流通之外，避免危机内容在未成年群体扩散。
- **审核管线位置**：E 类属 Stage 1 高危**同步**识别，**绝不进低危递送窗延迟**——危机必须秒级介入。

## 8. 给产品/法务的关键决策待办（设计阶段需拍板）

1. **<13 是否真开放？** 强烈建议 MVP **直接拒绝 <13 注册**（VPC 成本与 COPPA 风险极高）；若坚持开放，VPC 全链路（§1.4）必须先于上线完成。
2. **守护模式能否被"证明成年"解除？** 建议：可解除，但解除动作需**最高等级年龄保障**（§1.4 三方/面像），且**保留可逆**（误判申诉）。
3. **家长能否读信件正文？** 建议默认**否**（保护产品价值），仅在法域强制 + 危机/grooming 命中时按 §2.5 例外披露——此点须法务按各法域逐一确认。
4. **热线表与强制报告对象表**：建立**配置化 + 季度复核**机制（号码与法定路径会变）。
5. **CSAM 取证合规**：与法务确认各法域"不主动留存影像本体、哈希比对 + 即时移交"的具体落地路径。
