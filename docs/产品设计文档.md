# 信逢 · Inkling 产品设计文档

> Slogan：让社交回归真诚与纯粹
> 形态：移动优先的 Web 应用（PWA）
> 本文档由多视角设计 + 对抗式审查综合而成，作为后续开发的设计基线。

---

## 0. 一句话定位

**信逢是一座"漂流邮局"**：每天，你只能写一封信投入大海、打捞三次、认真拆开一封。
你看不到对方的脸、看不到"已读"、刷不出无限的人。
你只能像从前那样——慢慢写，慢慢等，慢慢遇见一个值得成为笔友的人。

> 核心承诺：**用"慢"换"真"。** 把社交从"泛泛之交的效率游戏"，变回"车马很慢、挚友可贵的郑重相遇"。

## 0.1 已确认的产品决策（2026-06-14）

| 决策项 | 选择 | 对设计的影响 |
|---|---|---|
| 目标市场 | **先做海外 / 港台** | 不走国内安全评估/ICP/网文/算法备案；改走目标地法规（香港 PDPO、台湾《個資法》、若涉欧盟 GDPR、若涉美未成年 COPPA）。详见 `docs/合规与本地化-海外.md` |

| MBTI 来源 | **允许用户自报型号** | 不做强制测评；需处理"未知/不确定"型号、自报不可信的降权、可选 mini-test 校准。匹配 MVP 用离散 16 型 + 兴趣 + 地理 |

## 1. 核心玩法与用户旅程

### 1.1 一封信的完整生命周期（状态机）

这是整个产品的脊柱，所有时间驱动逻辑都围绕它流转：

```
草稿 Draft
  └─→ 审核 Reviewing（AI 审核，藏进"在途"时间里）
        └─→ 在途 Delivering（按真实距离 1~24h，马车/信鸽/快马随机派送）
              └─→ 入池 Floating（进入公共漂流海，可被打捞）
                    └─→ 被打捞·预览锁 Hooked（10 分钟决策锁，仅锁这封信不被他人同时打捞）
                          ├─→ 超时未拆 → 回到 Floating（损失 1 次打捞额，保留拆封额）
                          └─→ 拆封 Sealed-Open（暂离池，启动 7 天回信窗口）
                                ├─→ 7 天内回信 → 成为笔友 Paired
                                └─→ 7 天未回信 → 回池 Recycled（清空上一位拆封者，不再被同一人打捞到）
                                      └─→ 多次回池 → 降权 Dimmed（曝光权重 ×0.7^N）
                                            └─→ 漂流满 30 天/回池≥3 次 → 归档 Archived（给作者一封温柔的系统安慰信）
违规任意阶段 → 冻结 Frozen
```

**关键计时常量**
- 预览决策锁 = 10 分钟
- 回信窗口 = **7 天**（自"信件送达拆封者"起算；**回信本身的在途时间不计入对方窗口**——远方笔友不因路途远而被误判超时）
- 漂流上限 = 30 天 / 回池≥3 次后归档

### 1.2 "打捞 ≠ 占有"：把"看一眼"和"认真读"解耦

- **打捞**（每天 3 次）：成本低，捞起即看到"半透名片"（部分标签 + 信件前几行）。
- **拆封**（每天 1 次）：成本高、不可逆。拆封时二次确认："拆封后这封信会暂时离开漂流池，只属于你们俩。确定吗？"
- 打捞产生 10 分钟"预览锁"，该信对其他打捞者隐藏；只有真正拆封才消耗拆封额并把信打成 Sealed-Open。
- 这样避免两个灾难：①多人争抢同一封信；②为"占坑"盲目消耗唯一的拆封额。

### 1.3 每日配额（稀缺感的底线）

- **基础配额固定不变**：1 投递 / 3 打捞 / 1 拆封。**不卖次数**（公平底线）。
- 未用完的当日配额**不累积、不折现**——"今天的车马，不等明天"。
- ⚠️ **冷启动期例外**：配额作为"运营杠杆"随本地池健康度动态放宽（详见 §8.1），密度达标后再收紧。MVP 不做复杂的"墨水值兑换券"动态配额体系（见 §9 决策）。

### 1.4 打捞预览：露出多少、反标题党

- 名片只露**文字标签**（MBTI 首字母 + 1 个地区标签 + 2 个兴趣标签），其余打码、随停留时长渐显。**不展示真人照片**（用信物图章/手绘头像代替）。
- 正文截取**第一个完整句子或前 60 字**（不截半句），并展示"今日信笺主题"提供写作语境。
- **反标题党**：AI 检测首段与全文语义相关度过低、或命中纯诱导词（"快拆""你绝对想不到"）→ 降权 + 提示作者重写。书信社交一旦允许首句钓鱼，整池会劣化成营销号腔。

### 1.5 新手破冰："每日信笺主题"

- "不知道写什么"是书信慢社交最大的流失点。首封信走 3 步引导：
  1. 选今日信笺主题卡（如"写给同样在异乡的人""你书架上最旧的那本书"）
  2. 可选 3 段式框架脚手架（一句问候 / 一段分享 / **一个抛给对方的问题**——天然提高回信率）
  3. 落款
- 新手前 3 封进入"新苗优先池"，老用户打捞时"新朋友"标签轻微加权；首封回信窗口延长到 10 天。
- 字数引导：建议 120~600 字，<50 字软提示，不硬拦。

### 1.6 拆封后的多分支结局与笔友长期关系

- **成为笔友** → 进入"笔友信匣"（一对一书信流），**保留在途延迟以维持慢节奏**（缩短为陌生信的 ~30%，老友车马更熟路）。
- **拆了不回**（窗口超时）→ 对原作者**永不显示"已读不回"**，只显示"你的信被人静静读过了"，信回池继续漂流。
- **笔友断联** → 14 天一次轻提醒；30 天休眠折叠；60 天可"封存"——把往来书信压成一枚带日期与地区的蜡封纪念章，存入"信缘博物馆"，可随时取出重启。**不做拉黑式删除，让关系有尊严地结束。**

### 1.7 防挫败兜底（慢社交的命门是"慢到没反馈 = 被冷落"）

- **空池兜底**：真人陈信 > 真人运营种子信（署名"漂流邮局"，透明标注）。
- **自己的信长期无人拆**（>72h）→ 自动提权 + 换一批受众重新分发；第 5 天可"换信封重投"（保留正文、换封面、软重置）。
- **去人格化文案**：所有负向结果永不显示拒绝者身份，统一翻译成"还在路上/缘分未到"。文案库示例："你的心意被人收下了，回信也许还在车马的路上。"

### 1.8 通知：与"慢"共生的轻提醒

- **强通知**仅用于两个节点：①笔友回信抵达；②回信窗口剩 <24h。
- **弱通知**（应用内角标）：信在途中、被打捞预览。
- "马车不打扰时段"（默认 23:00–7:00 延迟到次日清晨"晨间送达"）。
- 通知文案用古典时间单位增强体验："你的信由信鸽送出，约 2 个时辰后抵达。"

## 2. 匹配与递送算法

> 本质：一个**低频、高约束、强随机的双边稀疏市场**。每次曝光都极其昂贵。
> **北极星不是匹配数量，而是"值得拆封并在 7 天内回信"的高质量连接率。**

### 2.1 用户向量化与相似度

三段拼接：
- **M = MBTI 四维连续分** `[E/I, S/N, T/F, J/P]`，各归一到 [-1,1]（四维分开建模，才能支持后面"逐维度相似/互补"翻转）
- **I = 兴趣标签**：~200 个标签做 TF-IDF 加权（冷门同好如"羊毛毡"权重更高，更能命中真挚共鸣），可升级为 Embedding
- **G = 地理**：H3 网格，走独立的距离衰减项（不进余弦，避免量纲污染）

```
Sim(u,v) = wM·cos(M_u,M_v) + wI·[α·Jaccard(I) + (1-α)·cos(Emb)] + wG·exp(-d_km/τ_geo)
默认 wM=0.4, wI=0.35, wG=0.25, τ_geo=150km
```

### 2.2 MBTI 相似 / 互补双通道

- **相似配 Csim**：四维字母重合度，N/S 与 T/F 加权（最影响价值观与沟通风格）。
- **互补配 Ccomp**：**不是字母取反**（ISTJ vs ENFP 全反在现实中沟通成本极高），而是基于**荣格认知功能互补**——经典高互补对（INFJ-ENFP、INTJ-ENTP、ISFJ-ESFP）置高分。两张 16×16 矩阵离线预计算，O(1) 查表。

### 2.3 "结交偏好滑杆" = 可解释的趣味旋钮

滑杆 `p∈[0,1]`，0 = 最相似，1 = 风格最不一样：
```
effSim = (1-p)·Sim + p·(1-Sim)      // p=1 时把"低相似"当成高分
排序用温度 softmax 采样：P(v) ∝ exp(score(v)/T)
```
- `p` 控制"像/不像"，`T` 控制"确定/随机"，两个旋钮正交。
- **强制 ε-serendipity 保底**：每次打捞 3 个候选至少 1 个来自"相似度中位数 ±1σ 的随机带"（似曾相识的陌生人），防性格茧房。
- 产品化包装："滑向相似端 = 寻一个懂我的人（共鸣航线）；滑向相异端 = 遇一个全然不同的世界（远方航线）"；并设"命运随机"档。

### 2.4 投递/打捞架构：写时粗筛 + 读时精排（混合）

- **投递（写时）**：信件落库即写入倒排索引桶（地理 H3 / MBTI 型号 / Top-K 兴趣标签），初始化曝光预算。**不定向钉死到某人**。
- **打捞（读时）**：按打捞者偏好 `p` 召回候选集（约 200–500），实时精排 + 温度采样取 3 封（含 1 封 serendipity + 1 封公平性扶持）。
- 好处：滑杆即时生效、便于公平性干预、便于反茧房注入；候选集已粗筛，算力可控。

### 2.5 公平性与流动性（"每封信都该被看见"）

- **曝光预算**：每封信带 budget，被看 -0.5、被拆 -3；budget 多的信在召回中获得扶持加成。
- **反热门疲劳**：被反复打捞却无人拆/回的信，`hot_penalty = 1/(1+log(1+被捞次数))` 指数衰减，防"高颜值标签"霸屏。
- **冷启动扶持**：新用户首投信 boost ×1.5（限前 3 封）；新用户池强制混入"高回信率老用户"的信。
- 全链路打分总公式：
```
FinalScore = score_pref(p) × RepFactor(作者信誉) × hot_penalty × freshness × fairness_boost
```
每个因子是独立旋钮，便于 AB 调参，且每个因子都对应一个产品诉求。

### 2.6 真实地理 → 递送速度（"车马很慢"的产品魂）

Haversine 真实距离 `d` 分 5 档映射递送工具与到达时长：

| 距离 | 工具 | 时长 |
|---|---|---|
| <20km | 徒步信使 | 2–6h |
| 20–200km | 马车 | 12–24h |
| 200–800km | 信鸽 | 1–2 天 |
| 800–2000km | 飞鸽传书 | 2–3 天 |
| >2000km | 加急驿马/天涯专递 | 3–5 天 |

```
T = T_base(档) × (1 + 0.15·ln(1+d/d_base)) × jitter(0.8~1.2)
```
- **把等待做成期待**：地图上信使沿真实地理路径移动、"已翻过 XX 山/飞越 XX 江"的里程碑文案、抵达前推送。技术上前端按 ETA 插值动画即可，无需后端实时上报。
- **稀有递送工具**（低概率掉落、**只由书信行为解锁、不可购买**）：闪电飞鸽（减半）、迷途信鸽（+12h 但补偿稀有信手礼）、信天翁（跨 2000km 专属皮肤）。

### 2.7 反滥用：贝叶斯信誉分静默降权

```
Rep = (好评+被回信+α0) / (总曝光+被举报·w + α0+β0)   先验 α0=β0=2（新人中性）
RepFactor = Rep^γ  (γ=2，放大低分惩罚)
```
- 静默降权比直接封号更平滑（给改过机会）、不易被对抗试探。
- **反海王/反"广撒网"**：对"高拆封量但极低回信量"的行为漏斗单独打标限流（这类人消耗大量他人稀缺机会却不建立真实连接）。⚠️ 但要注意**杀猪盘特征相反**（高回信、长期深耕），需补关系层风控（见 §4.6）。

## 3. 内容安全与 AI 审核（产品命脉 + 合规红线）

> 核心思路：**以慢换准、分层裁决、高危即时**。

### 3.1 审核流水线（部分藏进车马时间窗，**但高危类必须秒级同步**）

```
L0 客户端/网关预过滤（<200ms）
L1 机器初审：规则引擎 + 敏感词 + 轻量分类模型（P95 < 2s，秒级同步）
L2 大模型语义复审（仅可疑件，<30s，可吸收进递送窗）
L3 人工复核（高风险/低置信，SLA 绑定该信 ETA - 30min 缓冲）
```

⚠️ **关键修正（来自合规审查）**：审核**双轨**。
- **机器初审始终秒级先行，立刻拦截四类高危**：涉政、诈骗、自杀/自残、联系方式——**绝不藏进慢递送**。
- 只有**低风险件的二次精审/人工复核**才可吸收进"车马时间窗"。
- **E 类危机干预脱离慢节奏，命中即时介入**（关怀 + 热线 + 人工）。
- 这是合规对"违法信息发现即处置"的硬时效要求，不能让位于体验叙事。

### 3.2 联系方式检测：六层联防（护城河，但需正确定位）

①正则强匹配（手机/QQ/邮箱/URL/wx/vx）→ ②归一化对抗（全角半角、emoji→数字、谐音"微/威/V/薇/wei"、拆字）→ ③语义意图（"换个地方聊""老地方见"）→ ④图像 OCR + 二维码解码 → ⑤隐写/夹带（藏头诗逐行首字、LSB 隐写）→ ⑥跨信件行为关联（同一作者多封信号码片段拼接）。

⚠️ **重要认知（来自审查）**：联系方式禁令**在对抗下不可能 100% 执行**（纯线下约定、分段拼接、手写图片）。因此：
- **护城河的真正定位 = 动机管理 + 经济成本 + 事后追责**，而非"检测 100%"。
- 用"冷却挽留 + 升级为站内更快笔友"**降低导流动机**。
- 目标从"零泄漏"改为"**可举报 + 可溯源 + 漏放后快速冻结**"。

### 3.3 不友好内容分级（国内合规语境）

5 类 × 3 级：A 辱骂骚扰 / B 性暗示色情 / C 政治敏感违禁（直接拦截、走合规快速通道）/ D 引流诈骗 / E 自残心理危机（**不走处罚，走干预**：关怀弹层 + 心理援助热线 + 人工）。

### 3.4 处罚阶梯（信用分"墨信值"双轨 + 联系方式重罚通道）

- 初始 100 分；普通违规轻 -5 / 中 -15 / 重 -40；阶梯：90+ 正常 → 75–89 软提示 → 60–74 限流 → 40–59 冻结投递 3–7 天 → <40 或重大违规 冻结 30 天 → 累犯永封。
- **联系方式走独立重罚通道**：首次严重警告 + 限流 7 天 → 二次冻结 15 天 → 三次永封（对应原构思）。
- ⚠️ **程序正义（PIPL 第 24 条）**：任何显著影响用户权益的处置（冻结、永久降权）**不得仅靠自动化裁决**，置信度未达高阈值必须人工复核；提供清晰申诉入口与秒级恢复 + 配额补偿；首违从轻。
- 墨信值每月无违规自动回升，给真诚用户改过空间。

### 3.5 违规信件处置：静默拦截 + 差异化告知

- **接收方一律采用"信件不存在"模型**——违规信从不进池，从根上避免二次伤害和猎奇。
- 对作者：可挽救类（低置信疑似联系方式）→ **退回 + 高亮疑似段 + 改写建议，不扣次数不冻结**；明确违规类 → 告知类别 + 扣分；红线类 → 模糊提示防对抗试探。

### 3.6 AI 工程落地

- L2 结构化 JSON 输出：`{contact_info, harmful{category,level,confidence}, suicide_risk, overall_action}`。
- 置信度三段：≥0.85 自动执裁 / 0.55–0.85 人工队列 / <0.55 放行但采样。
- **成本控制**：信逢日投递量极小（人均 1 封），只有 5–15% 可疑件触发大模型，且慢递送允许批处理错峰。第三方 API 故障时**对高危类保守拦截**，绝不无审核放行。

### 3.7 未成年人保护 + 隐私 + 实名（⚠️ 致命级，见 §8.5/§8.6）

- 强实名（手机号实名，必要时人脸/活体）；**强烈建议 MVP 仅限 18 岁以上并以技术手段拦截**，大幅降低法律敞口。
- 审核遵循"机器为主、人工最小必要、脱敏留痕"——人工只看脱敏片段、隐去身份、二次授权才能关联、全程可审计。
- 隐私政策**显著告知**"信件经自动安全审核、极少数高风险件可能人工脱敏复核"并取得**单独同意**。

## 4. 装扮系统 · 虚拟经济 · 信手礼

> 经济铁律：**卖表达不卖优势、卖季节不卖概率、买不到真挚。**

### 4.1 三层经济骨架（MVP 先极简，完整版再上）

- **墨滴（软货币）**：日常基础外观、图鉴点亮；可温和购买，**日产硬上限**。
- **笔友值（关系深度）**：绑定到**单段关系**，只能由真实双向通信产生，**不可购买、不可转账**。
- **真诚徽印（信誉）**：被不同陌生人"点亮真诚"累积，决定顶级/双人皮肤资格，**永不售卖**。

把"活跃度 / 关系深度 / 人品信誉"三件事彻底解耦——从机制上保证买不到真挚。

### 4.2 反灌水货币学：奖励"被回应"而非"发送量"

```
墨滴_单封 = 基础10 × 质量系数Q(0.3~1.5) × 关系新鲜度N
Q 由字数 + AI 真诚分 + 历史被回信率决定
```
投递本身只给小额，大头在"收到回信 +15""被点亮真诚 +25"——刷量者拿不到钱。

### 4.3 五大装扮品类 × 五稀有度

信封 / 信纸 / 火漆封缄 / 马车皮肤 / 信鸽皮肤；稀有度：常墨→雅集→珍藏→孤本→传世。
- 四件套 + 挂坠组成"信笺套装"，**齐套触发隐藏动效**（"江南烟雨"齐套时信鸽飞过留水墨拖尾）。
- 稀有外观 = 稀有行为/经历（关系里程碑、地域全图鉴、真诚徽印），**而非氪金**。

### 4.4 信手礼 × 地理：「中国信驿地图」图鉴

- 每个地级市/文化区设专属信手礼（泉州簪花围、景德镇青花小盏、潮汕工夫茶具…）。
- **只能从"与该地区笔友建立联系并通信"后由对方随信附赠或本地解锁** → 把"集邮欲"反哺地理多样性匹配，驱动跨地域慢社交。
- 集齐一省 → 省级礼盒 + 称号；驿站修缮动画给长期目标感。
- **反作弊**：需真实距离 >150km 的关系才计入跨域点亮（依赖可靠定位 + IP + 行为图谱反代理）。

### 4.5 温和商业化（详见 §8.3 商业模式）

外观直购 / 笔友季卡年卡订阅 / 季节节气限定礼盒（**明码标价、非随机**）/ 城市文化礼盒（文旅 IP 联名，部分收益回馈非遗）。
**禁区**：不卖打捞拆封次数、不卖匹配优先权、不做抽卡卡池、不做付费买好友。

### 4.6 去 FOMO 的"年轮式"限定

二十四节气 / 节日限定采用**循环复刻**——"今年错过明年还能再遇"，过季可用墨滴补领（去首发动效保留首发荣誉）。集满一年 24 节气 → 年度"岁时传世"套装。把 FOMO 转化为细水长流的年度仪式感。

## 5. 情感设计与"慢社交"理念

> 护城河不在功能，而在**情绪质感**——让用户打开 App 那一刻就从"刷手机的焦虑态"切换到"写信的沉静态"。

### 5.1 世界观：「漂流邮局 × 信使联盟」

所有功能词换皮成世界观词汇（"语言宪法"）：投递=放漂、漂流池=漂流海、打捞=拾信、拆封=启信、回信成功=结缘、断联=信缘暂歇、装扮=信驿铺子、信手礼=乡物/驿礼。
建立《信逢辞典》单一事实来源；UI 文案**禁止出现**"匹配/聊天/在线/已读/粉丝/关注"等速配词（做成 lint 规则）。

### 5.2 产品宪法第一条：我们坚决不做的 8 件事

1. 无限右滑/信息流连续浏览（每天 3 次打捞，刷完即"今日漂流海已平静"）
2. 颜值排序/头像优先（只展示文字标签）
3. 已读回执（**永不显示"对方已读"**，消除被晾的羞耻）
4. 在线状态/最近活跃
5. 即时聊天气泡/"对方正在输入"
6. 未读红点轰炸（用柔和铃铛代替数字角标）
7. 连续登录/签到打卡式 KPI
8. 粉丝数/笔友数排行榜

新手引导第 3 屏即用"我们不做什么"做价值观筛选，自筛掉求速配的用户。

### 5.3 三段式仪式（把"功能操作"升维成"情感事件"）

- **放漂（写）**：沉浸编辑器，信纸/字体/钢笔笔触音效，最少字数软门槛。
- **启信（拆）**：每天仅 1 次的最重仪式——拆封手势（撕开/解火漆）+ 一次性音效 + 0.8s"墨迹显影"留白，**不能秒读**。
- **结缘（回）**：盖上自己的信物图章再放飞信使。

全局动效偏慢（过渡 300–500ms，模拟物理惯性），刻意制造"呼吸留白"。

### 5.4 健康留存引擎：用 FOSO 替代 FOMO

> FOSO = Feeling Of Something Outgoing，"有一份心意在路上"的正向期待，而非"会错过什么"的损失焦虑。

- 回访由**他人驱动的、有限的、温暖的事件**触发（信件抵达、有人拾起你的信、笔友来信），**不可被用户自己无限刷新制造**。
- 每日机会用尽 → "今日已满"的满足型落幕，把"没得玩了"重构为"今天够了"。
- 北极星指标改为 **WAR（周活跃回信率）+ 笔友 30 日存活率**，接受低频但高质。
- **闭馆/静默假期**：用户可主动开启"闭馆 7 天"，期间信件暂存不流失，**把"离开"设计成被祝福、无惩罚的行为**（反黑暗模式旗帜设计）。

### 5.5 情感安全网（陌生人社交最大风险是"沉默即伤害"）

逐场景温柔兜底，**所有失败/拒绝态文案禁止出现"失败/被拒/无人/对方未"**，统一替换为海浪/旅途/缘分的隐喻：
- 无人拾起 → "你的信被海浪温柔地送回了，要不要换一片海再放一次？"
- 拆了未回 → "信又回到漂流海继续旅行了。"
- 笔友断联 → 提供"**告别信**"出口（信纸印"此信无需回复"），让关系有尊严地结束。
- 收到伤人内容 → AI 先于用户拦截并折叠，附一封"漂流邮局慰问信"。
- **树洞漂流瓶**：允许写不期待回信的信，给只想倾诉的孤独人群一个不被拒绝的出口。

### 5.6 正向激励：只奖励"用心"，从机制上饿死海王

- **"被珍藏"回响**（全产品最催泪、最契合品牌内核）：收信人把一封信收进信匣珍藏，写信人收到——"你写的『___』，被一个陌生人小心地收进了信匣。" **不显示是谁、不可量化、无法刷量**，却是用户自发截图传播的高光时刻。
- "笔触温度"徽章基于回信质量与被珍藏率，**仅自己与笔友可见，不做公开榜单**。
- 反海王：同一作者跨多段关系的语义雷同开场 → 行为指纹降权（不止靠文本相似度）。

## 6. 技术架构（Web / PWA）

> 本质：**低频强约束的异步社交 + 时间驱动状态机 + 轻量内容安全**，**不是高并发 IM**。反其道而行，避免过度设计。

### 6.1 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | Vue3 + Nuxt3（SSR）+ Pinia + UnoCSS + GSAP | 国内分享秒开、免 App Store、可挂微信浏览器；GSAP 做书信/车马仪式动效 |
| 后端 | Go(Gin/Kratos) 或 Node(NestJS) 长驻服务 | 承载状态机 + 定时调度 + WebSocket |
| 主库 | PostgreSQL 16（PostGIS + pgvector + JSONB） | 强一致事务根治拆封竞态、地理、画像向量、灵活标签 |
| 缓存/锁/配额 | Redis 7 | 每日配额计数、分布式锁、ZSet 排序 |
| 延时队列 | RabbitMQ（延时插件）或 RocketMQ（原生定时消息） | 递送计时与 7 天回池 |
| 对象存储 | 阿里云 OSS / 腾讯云 COS | 装扮静态资产 + 用户图 |
| 定时任务 | XXL-JOB / Asynq / BullMQ | 配额重置 + 兜底巡检 |
| 推送 | WebSocket + Web Push / 微信服务号模板消息 | 信件抵达通知（Web 无原生推送的补充通道）|

取舍排序：**一致性 > 性能 > 成本**。读多写少，PG 1 主 2 从。

### 6.2 核心数据模型（约 13 张表，以信件状态机为中心）

`users` / `user_profiles`(mbti, interest_tags JSONB, match_pref_ratio, persona_vector) / `letters`(status, pool_visible_at, expire_at) / `letter_cards`(脱敏预览快照) / `fishing_records` / `unseal_records`(reply_deadline) / `penpal_relations` / `reply_messages` / `delivery_tasks` / `daily_quotas` / `decorations` / `regional_gifts` / `audit_records` / `penalty_records`。

- `letters.status` 用枚举 + 严格状态机校验，流转走带乐观锁(version)的 CAS。
- **地理只持久化 GeoHash 前 5 位（±2.4km），原始经纬度内存即弃绝不落库。**

### 6.3 三大技术难点

1. **递送计时 + 7 天回池**：`DB 权威时间戳 + 延时队列触发 + 定时巡检兜底`三件套。所有触发先读 DB 状态再 CAS 执行 → 天然幂等。⚠️ 时间承诺是法律/信任红线，边界争议一律**向用户有利方向裁决**（宁可多给宽限），并显示精确倒计时。
2. **打捞-拆封并发竞态**：`Redis 原子锁(SET NX EX) + DB 乐观锁(CAS WHERE status=在池 AND version=v)`双保险，数学上杜绝一封信被两人拆封；配额扣减在同一事务内原子完成防刷。
3. **AI 审核集成**：异步队列 + 双层（本地硬规则 + 第三方内容安全 API）+ 高危秒级先行；熔断降级时对高危保守拦截。

### 6.4 MVP 技术范围

单体后端 + PG + Redis + RabbitMQ 一把梭，**不上微服务/不上向量库**（MVP 匹配用"地理 + 兴趣标签 + MBTI 规则 + 同圈层随机"即可，pgvector 留给演进）。

## 7. 最佳补充点子（Brainstorm 精选）

1. **邮戳收藏化**：递送工具送达盖不同邮戳，集齐一地区所有工具邮戳解锁该地区信手礼——把"等待"变成开盲盒式正期待。
2. **换信封重投**：长期无人拆的信换信封软重置，自然制造"装扮影响被打捞率"的轻博弈，让装扮有真实社交价值。
3. **偏好滑杆"反差盲盒"彩蛋**：拉到极端"最不一样"时偶发"命运的反面"匹配，成功结友得"磁极"纪念章。
4. **信缘博物馆 / 蜡封纪念章**：关系体面退出、可珍藏可重启——高频社交产品做不到的强情感留存资产。
5. **一句话被珍藏的回响**：纯情感、不可兑换、无法刷量，却是最催泪、最易自发传播的高光时刻。
6. **信使旅途明信片 + 可收藏旅程地图**：信在途经过虚构地名（忘潮湾、迟信岛）生成可收藏明信片，把"慢"的负担转化为"慢"的奖励。
7. **告别信 / 不必回复的信**：让关系有仪式地结束，给孤独人群不被拒绝的倾诉出口。
8. **危机守护信鸽专线**：对自残/心理危机不走处罚，触发专属"守护信鸽"——把最危险的内容转化为产品最有温度的时刻。

## 8. ⚠️ 关键风险与必答题（来自对抗式审查，含原构思未覆盖的致命问题）

> 这些是"做得再美也可能让产品死掉/出大事"的结构性问题。**前 6 条优先级高于一切玩法细节。**

### 8.1 冷启动死亡螺旋【致命】

按地理 H3(3-4km)+MBTI 型号+兴趣三重分桶后，用户基数不足时任何用户的本地候选池约等于空。"打捞侧"能靠运营种子信兜住，但"**回信侧兜不住**"——种子信背后没真人会回，用户第一周体验 = 单向的空。
**解法**：放弃"全国漂流海"幻想，改为**单点高密度封闭冷启动**（一所大学/一个文艺兴趣社群），密度做到"任意时刻本地活信 ≥ 阈值 且 新用户 7 天首次结友率 ≥ 阈值"再开第二个点。配额、匹配宽度、种子信比例全部做成**随池子健康度动态收放的运营杠杆**，而非写死的产品信仰。**密度没达标前绝不投放拉新**（往漏水的桶里倒水是最贵的死法）。

### 8.2 "慢" vs 留存/增长的根本矛盾【致命/结构性】

核心正反馈延迟最长可达 10 天+；每日配额用尽压制 DAU 与时长，广告/DAU 变现模型不成立。
**解法**：从一开始就**承认这是低频产品**，按"低频高价值订阅 + 收藏付费"建模并写进团队/投资人共识，避免增长压力中途逼产品走回速配。新手前 7 天**人为制造一次确定性的早期成功**（高回信率真人志愿者池 + 运营信使，保证首封 48h 内有真人质量回信）。

### 8.3 性别供需失衡与女性安全【致命 / 原构思完全缺失】

所有匿名陌生人社交都会演化为男性供给过剩、女性被淹没/被骚扰 → 女性流失 → 男性失去对象 → 整体崩盘。
**解法（当一等公民处理）**：
- 女性收件侧**保护性限流 + 质量门槛**，避免被淹没；女性的信获得更高分发权重以鼓励供给，男性需通过"被回信率/真诚徽印"赚取分发权重。
- **上线即提供**拉黑/隐身/举报，对女性默认更严的守护模式（不等数据积累）。
- 冷启动主动运营女性社群、控制初始性别比接近 1:1 再放量。

### 8.4 笔友导流到微信 → 平台空心化【高】

六层联系方式检测本质在和用户根本需求作对：拦松 = 空心化，拦严 = 误伤 + 体验崩。
**解法**：**承认无法靠技术封死导流**，改为靠"站内关系增值"降低动机——把笔友信匣做成微信替代不了的体验（专属信纸/双人皮肤/信缘博物馆/在途仪式/被珍藏回响）。KPI 从"零导流"改为"**关系在站内存续的时长/深度**"。误伤风险降到最低：疑似联系方式一律先"拦截退回 + 提示修改、不扣分不冻结"。

### 8.5 国内运营强制资质与备案【致命 / 原构思完全缺失，上线门禁】

本产品 = 陌生人匹配 + 公开 UGC + 私信 + 算法推荐 + 生成式 AI，几乎必然被认定"具有舆论属性或社会动员能力"。**写任何业务代码前**先做合规清单与申报路线图（go/no-go gate，合规未过不得灰度）：
- ✅ 公安网安**安全评估**（双新评估，覆盖实名、内容审核、应急处置、记录留存 ≥6 个月、违法信息处置）
- ✅ **ICP 经营许可证 / EDI**
- ✅ **网络文化经营许可证**（装扮收费、信手礼数字商品）
- ✅ **算法推荐服务备案** + 提供"关闭个性化推荐"选项
- ✅ **生成式 AI 备案** + 所有 AI 生成内容（暖场信/重写建议/慰问信）显著标识"AI 生成"
- ✅ 陌生人社交品类的实名核验 + 反诈要求

### 8.6 未成年人保护【致命】

陌生人匹配 + 真实地理 + 长期一对一私密通信 = grooming（诱导性侵）最理想温床。
**解法**：①**强烈建议注册即明确"仅限 18 岁以上"并技术拦截**，降低法律敞口；②若做未成年人，必须强实名（人脸/活体）确认成年才解锁完整匹配，未成年账号禁止与陌生成年人匹配、零容忍线下约定语义、关闭精确地理；③上线 grooming 专项行为模型；④建立强制报告与留证流程（《未成年人网络保护条例》）。

### 8.7 其他高优先级风险

- **杀猪盘/PUA**【高】：慢节奏长期书信是情感诈骗最佳土壤，且其特征（高回信、长期深耕）与反海王漏斗相反。需补**关系层风控**：对"长期通信后突然出现金钱/投资/转账话术"跨信件建模、私信内置反诈提示、对接国家反诈中心。
- **通信秘密 vs 人工审核**【高】：书信被主观认定为私密通信，人工复核若不透明会被指"偷看私信"。需单独同意 + 脱敏 + 留痕审计 + 短留存。
- **商业模式/LTV 未测算**【高】：低频 + 禁卖次数/抽卡/优势，只靠装扮/订阅/收藏，需明确 ARPU/付费率/LTV 假设能否覆盖陌生人社交极高的获客成本。
- **病毒传播缺失**【高】：全私密设定扼杀了社交产品最有效的免费获客。需补克制但存在的传播钩子（被珍藏回响可分享、信件美图生成分享卡、邀请制裂变各得装扮），但不做公开排行榜。

## 9. 设计矛盾的决策记录（已拍板）

审查发现原构思与各维度方案间存在内部矛盾，逐条给出决策：

| # | 矛盾 | 决策 |
|---|---|---|
| 1 | 极简调性 vs 经济系统极度复杂 | **MVP 砍掉复杂经济**，只留最小装扮；完整版的经济系统必须服从极简调性（收敛品类、不做积分墙） |
| 2 | 7 天固定窗口 vs 远距离动态宽限 | **统一规则**：7 天自"送达拆封者"起算；**回信的在途时间不计入对方窗口**；前端显示精确倒计时 |
| 3 | AI 暖场信 ≤1/3 vs 冷启动每次打捞都要有内容 | **MVP 用真人运营种子信**（透明署名"漂流邮局"）替代 AI 信；AI 信若用必须强标识、极克制、真人内容充足后下线 |
| 4 | 慢审藏进车马 vs 高危内容须即时处置 | **审核双轨**：高危类秒级同步先行，只有低风险件二次精审可吸收进递送窗 |
| 5 | 藏头诗官方玩法豁免审核 vs 联系方式护城河 | **砍掉豁免通道**：藏头内容同样全量过审，保留藏头作为浪漫玩法但无审核例外 |
| 6 | 被读不回不暴露身份 vs 作者需成长反馈 | 保留不暴露身份；给作者**仅基于自己信件的 AI 写作建议** + 聚合数据，不涉及他人 |
| 7 | "成笔友奖励额外拆封券" vs 反速配理念 | **砍掉该奖励**（用增加曝光奖励社交成就会诱导敷衍速配）；重度用户的出路是"更深"而非"更多次" |
| 8 | 真实地理 vs 冷启动跨区域召回 | 冷启动期承认跨区，但**明确告知用户"今日为你扩大了海域"**，且信手礼跨域收集仍以真实距离为准 |
| 9 | 全私密无炫耀 vs 增长需病毒传播 | 保留"无公开排行榜"，但开放**可选的**对外分享（被珍藏回响、信件美图卡、邀请裂变） |
| 10 | 隐私最小化 vs 风控/取证需要 | 风控数据**隔离存储、最小留存、不外显不商业化**；满足公安留存要求的同时设上限脱敏 |

## 10. MVP 范围与演进路线

### 10.1 MVP 唯一要验证的假设

> **陌生人是否愿意为一次"慢而真诚"的书信连接，投入精力写信，并在收到回信后留下来。**
> 装扮经济、收集图鉴、复杂匹配算法、关系仪式都是"假设成立之后才值得做的护城河"。先用最低成本证伪/证实唯一假设。

### 10.2 MVP 必须保留

**核心循环**：注册(实名) + MBTI/标签 → 每日 1 投 3 捞 1 拆 → 打捞预览 + 拆封 → 7 天回信成笔友 → 基础笔友信匣。递送先用固定/粗档时延的信鸽动画。匹配先用"地理 + 兴趣标签 + MBTI 规则 + 同圈层随机"。

**合规与安全底座（不可砍）**：
- 强实名 + 明确 18+ 准入与技术拦截
- 机器审核**秒级先行拦截四类高危**（涉政/诈骗/自杀/联系方式）
- 联系方式基础检测（正则 + 敏感词 + 基础语义 + 图片 OCR）+ 一家第三方内容安全 API + 人工抽审
- 清晰的**举报-拉黑-隐身-处置-申诉**闭环（女性安全，不可省）
- 违法信息发现即处置 + 留存 ≥6 个月
- 隐私政策对"信件经自动审核、极少数人工脱敏复核"的显著告知 + 单独同意
- **上线前完成安全评估、ICP/网文/算法/生成式 AI 备案 = go/no-go 门禁**

### 10.3 MVP 坚决砍掉（全部进演进路线）

双货币/墨水值/补给券等动态配额经济、五品类×五稀有度装扮矩阵、熔炉重铸/驿站修缮/24 节气印章册、信手礼地图 LBS 收集、偏好滑杆的符号翻转+温度采样+互补矩阵+ε-serendipity 全套、稀有递送工具掉落/邮戳收藏、信缘博物馆/蜡封纪念章/告别信、真诚徽印/真诚之星荣誉体系、AI 暖场信复杂比例规则、藏头诗官方玩法、公开信展轮播、树洞/孤独识别/危机干预专线（须专业团队 + 法务到位后再做）。

### 10.4 MVP 必看指标（按重要性）

1. 新用户 7 天内首次成功结为笔友的比例（决定能否开新池）
2. 投出的信被真人回信的比例（回信侧供给健康度）
3. 拆封率 & 拆封后 7 天回信率（核心假设是否成立）
4. 成为笔友后的"关系半衰期/导流流失率"（商业模式命根）
5. 联系方式漏放率（合规门槛）
6. 性别比 & 女性次日留存（性别死亡螺旋预警）

### 10.5 演进路线

**阶段一（MVP，2–3 月）**：核心循环 + 合规安全底座 + 单点封闭冷启动。
**阶段二（粘性）**：装扮系统 + 信手礼收藏 + 成长解锁 + 笔友关系仪式。
**阶段三（精度）**：匹配升级为向量召回（pgvector→Milvus）+ 偏好滑杆精调 + 真实距离精算 + 递送工具皮肤。
**阶段四（生态）**：城市文旅联名 + 公开信展 + 季节活动 + 跨地域运营。
