### 0.1 已实现【实现】

- **核心循环全链路**：注册（邮箱/密码）→ 自报 MBTI/兴趣 → 写信（审核 → 在途）→ 漂流海打捞（10 分钟预览锁）→ 拆封 → 7 天回信结缘 → 笔友信匣往来。

- **时间驱动状态机**：`delivery.scheduler` 每 20 秒轮询处理「入海 / 预览锁回收 / 回信窗口预警 / 超时回池或归档 / 笔友送达 / 漂流到期归档」，幂等（先读后条件更新，`count===1` 才发通知）。
- **每日配额**：1 投递 / 3 打捞 / 1 拆封（UTC 自然日）。
- **匹配**：自报 MBTI（相似 / 荣格互补 / 偏好滑杆融合）+ 兴趣 Jaccard + 地理就近 规则打分 + Top-K 轻随机（偶遇感）。
- **内容审核**：本地规则（归一化对抗还原 + 联系方式/不友善检测）+ `ModerationProvider` 抽象（remote 为 fail-closed 桩，`local` 默认）。
- **风控闭环**：举报（按 distinct 举报人累计）/ 拉黑 / 隐身 / 申诉落表；高危内容累计与举报累计自动冻结；**封禁 / 冻结 / 注销在请求期即时生效**（含存量 access token 与 refresh token）。
- **隐私合规底座**：GDPR 全量结构化导出；注销请求由**匿名化执行器**定时推进（每 10 分钟）。
- **通知**：去人格化弱通知（5 类）+ 前端轮询通知中心。
- **基建**：Prisma 迁移（additive 原则）、Vitest 单测 + 集成/e2e、CI 三档（unit / integration / images）、限流防爆破、PWA（可安装 + 离线壳）、生产部署预案全套（未真机验证）。

## 1. 产品定位与核心玩法【实现】

### 1.1 定位

**信逢是一座「漂流邮局」**：每天，你只能写一封信投入大海、打捞三次、认真拆开一封。你看不到对方的脸、看不到「已读」、刷不出无限的人。你只能像从前那样——慢慢写，慢慢等，慢慢遇见一个值得成为笔友的人。

> 核心承诺：**用「慢」换「真」**。把社交从「泛泛之交的效率游戏」，变回「车马很慢、挚友可贵的郑重相遇」。

定位是**低频、高约束、异步**的书信社交（不是高并发 IM）；北极星是「值得拆封并在 7 天内回信」的高质量连接率，而非匹配数量。

### 1.2 一封信的完整生命周期

```
草稿 DRAFT → 在途 DELIVERING → 漂入海面 FLOATING
  → 被打捞·预览锁 HOOKED（10 分钟，仅锁这封信）
       ├─ 超时未拆 / 主动放回 → 回到 FLOATING（损失 1 次打捞额，保留拆封额）
       └─ 拆封 SEALED_OPEN（暂离池，启动 7 天回信窗口）
             ├─ 7 天内回信 → 结缘 PAIRED（进入笔友信匣）
             └─ 7 天未回信 → 回池重漂 FLOATING（recycleCount+1）
                   └─ 回池 ≥3 次 或 漂流满 30 天 → 归档 ARCHIVED
```

（`REVIEWING / RECYCLED / DIMMED / FROZEN` 为预留态，无写入方，由 `enum-drift` 测试守护与 shared 枚举一致。）

**关键计时常量**（可在 `.env` 覆盖，默认值在 `packages/shared/src/constants.ts`）：

| 常量 | 默认 | 说明 |
|---|---|---|
| 预览决策锁 | 10 分钟 | 打捞后仅这封信对你锁定 |
| 回信窗口 | 7 天 | 自「送达拆封者」起算；回信本身的在途**不计入**对方窗口 |
| 漂流上限 | 30 天 | 到期归档 |
| 最大回池次数 | 3 | 达上限归档 |
| 投递→入海延时 | 30s（本地）/ 生产可调 | 演示「漂入海面」 |
| 笔友往来在途 | 按距离 4–96h × scale | 生产 `DELIVERY_HOURS_SCALE=1`，测试 0 即时 |

### 1.3 每日配额（稀缺感的底线）

- **基础配额固定**：1 投递 / 3 打捞 / 1 拆封，**不卖次数**（公平底线）；未用完不累积、不折现。
- 冷启动期配额作为运营杠杆可动态放宽（见 §9 风险），MVP 不做复杂动态配额体系。

### 1.4 「打捞 ≠ 占有」

- **打捞**（3 次/天）：低成本，看到「半张文字名片」（部分标签 + 信件前几行），产生 10 分钟预览锁。
- **拆封**（1 次/天）：高成本、不可逆，二次确认后启动 7 天回信窗口。
- 这样避免两个灾难：①多人争抢同一封信；②为「占坑」消耗唯一的拆封额。

### 1.5 破冰与反标题党

- 「每日信笺主题」卡（如「写给同样在异乡的人」）+ 可选三段式框架（问候 / 分享 / **一个抛给对方的问题**——天然提高回信率）。
- 字数 50–1000（下限防灌水，前端软提示 120–600 建议区间）。
- 预览正文截取第一个完整句或前 60 字（不截半句）；首段与全文语义相关度过低 / 纯诱导词 → 降权（**【演进】**）。

### 1.6 世界观词典（界面文案硬约束）

投递=放漂｜在途=信鸽振翅/车马劳顿｜入池=漂入海面｜打捞=拾信｜预览锁=拆封前的犹豫｜拆封=启信｜回信窗口=回信潮汐｜结缘=成为笔友｜超时回池=信重新漂回海面｜拉黑/举报=退回邮局/投诉信使｜隐身=闭关。

**UI 文案禁止出现**：匹配 / 聊天 / 在线 / 已读 / 粉丝 / 关注 / 正在输入 / 最后活跃（**【演进】**：做成 lint 规则）。

### 1.7 产品宪法：坚决不做的 8 件事

1. 无限右滑 / 信息流连续浏览（每天 3 次打捞，刷完即「今日漂流海已平静」）
2. 颜值排序 / 头像优先（只展示文字标签，不展示真人照片）
3. 已读回执（**永不显示「对方已读」**）
4. 在线状态 / 最近活跃
5. 即时聊天气泡 /「对方正在输入」
6. 未读红点轰炸（用柔和铃铛角标）
7. 连续登录 / 签到打卡式 KPI
8. 粉丝数 / 笔友数排行榜

### 1.8 情感设计（FOSO 替代 FOMO）

- 回访由**他人驱动的、有限的、温暖的事件**触发（信件抵达、有人拾起你的信、笔友来信），不可被用户自己无限刷新制造；每日机会用尽 =「今日已满」的满足型落幕。
- 三段式仪式：**放漂**（沉浸编辑器）→ **启信**（火漆拆封仪式，每天仅 1 次的重仪式）→ **结缘**（盖信物图章）。
- 全局动效偏慢（过渡 300–500ms），刻意制造呼吸留白；尊重 `prefers-reduced-motion`。
- **情感安全网**：失败/拒绝态文案禁止出现「失败/被拒/无人/对方未」，统一替换为海浪/旅途/缘分隐喻（如「信又回到漂流海继续旅行了」）；提供「告别信」出口（**【演进】**，MVP 为温和通知）。
- 「被珍藏」回响、树洞漂流瓶等情感机制为**【演进】**。

## 2. 界面与交互

> 已实现页面见 `apps/web/pages/`；本节保留整体信息架构、关键流程与边界态原则。详细线框以代码为准。

### 2.1 信息架构（四 Tab）

```
启动/鉴权层（无 Tab）：启动屏 → 登录/注册 → 首次资料引导（笔名→MBTI→兴趣→地理授权）
[Tab1] 漂流海（默认首页）：海面 → 打捞预览卡 → 拆封读信 → 回信
[Tab2] 我的信件：在途/已送达/已结缘 + 写信编辑器（FAB）
[Tab3] 笔友信匣：笔友列表 → 往来会话（保留在途延迟，非即时聊天）
[Tab4] 我的：资料 / 设置（闭关·通知）/ 安全中心 / 账号与隐私（导出·注销）
```

- 投递入口在「我的信件」（FAB），不在漂流海（「打捞别人」vs「管理我寄出的」的心智区分）。

### 2.2 关键流程约束

- **注册**：邮箱 + 密码 + 笔名 → 首次资料引导。**【实现】**（年龄门控与守护模式已于 2026-10-03 取消，见 §5.1）
- **写信**：编辑器 →「封缄寄出」二次确认 → 审核（秒级，高危拦截可修改重投）→ 在途 → 入海。
- **打捞**：抛竿动画（1–2s 仪式感）→ 预览卡（10 分钟倒计时，可放回）→ 拆封（二次确认 + 火漆动画）→ 读信（7 天倒计时常驻）→ 回信。
- **结缘**：回信审核通过 → 双印章合拢动画 → 进入笔友信匣。**【实现】**（动画为 GSAP 简化版）

### 2.3 去人格化（硬约束）

- 永不显示「已读 / 在线 / 最后活跃 / 正在输入」；数据层不存这些字段。
- 打捞预览不露真人照片；距离只给模糊文案（「近在咫尺 / 约 N 公里外 / 天涯之遥」）。
- 所有负向结果永不暴露拒绝者身份。

### 2.4 边界态（空 / 加载 / 错误 / 被拒 / 超时）

| 场景 | 文案基调 | 动作 |
|---|---|---|
| 海面无信 | 「此刻海面平静，稍后再来碰碰运气」 | 返回 |
| 列表失败 | 「信袋暂时打不开」 | 重试（与「空」区分渲染）|
| 拆封并发冲突 | 「这封信刚被另一位旅人拆开了」 | 次数返还 + 提示 |
| 审核被拒 | 「这封信未能通过分拣」+ 分级原因 | 修改后重投（保留草稿）|
| 预览锁超时 | 「你犹豫太久，信漂走了」 | Toast |
| 窗口流失 | 「潮汐已落，这封信重新漂回了海面」 | 温和通知 |
| 配额耗尽 | 「明日潮汐再启」 | 入口灰态 |

### 2.5 动效与节奏（GSAP）

- 在途进度用「信鸽逐帧飞行 / 车马行进」表达，不用百分比进度条；进入页面才推进一帧，严禁秒级实时刷新。
- 拆封仪式按压 0.6s 触发火漆裂开 + 信纸展开（`power2.out` + 轻微抖动）；结缘动画为最重正反馈。
- 全局只用 transform/opacity；`gsap.matchMedia` + `prefers-reduced-motion` 降级为淡入淡出。**【实现】**

## 3. 匹配与递送

### 3.1 自报 MBTI 的处理【实现·简化】

- 不做强制测评；支持「我还不确定」= `UNKNOWN`（**第一公民**，空着也能注册，匹配降级为「兴趣+地理」）。
- 自报可信度：设计为三档 `confidence`（unknown/unsure/confident）降权；**当前实现**简化为 `UNKNOWN → 中性 0.5`，未实现 unsure/confidence 字段（**【演进】** mini-test 校准与 `verified` 加成）。

### 3.2 相容打分（实现口径）

```
Score = 0.4 · MBTI亲和 + 0.35 · 兴趣Jaccard + 0.25 · 地理就近      // ocean-score.ts
```

- **MBTI 亲和** `mbtiAffinity(a, b, p)`：`(1-p)·相似度 + p·互补度`。
  - 相似度 = 四维字母重合度，S/N 与 T/F 维度权重 1.5（最影响价值观与沟通风格）。
  - 互补度 = **荣格认知功能互补**（非字母取反）：8 对「黄金互补对」给 0.9，其余按差异度温和给分（≤0.6）。
  - 偏好滑杆 `p∈[0,1]`：0 = 寻相似（共鸣航线），1 = 遇互补（远方航线），0.5 默认。
  - 任一 `UNKNOWN` → 亲和度恒 0.5（中性）。
- **兴趣 Jaccard**：交集/并集；任一为空返回 0。
- **地理就近**：`e^(-km/150)` 衰减；距离未知（任一方无 geohash）给中性 0.3。
- **召回与抽样**：候选（在池、非自己、未捞过、非拉黑、作者非隐身）按 `poolVisibleAt` 升序取 50 封 → 打分排序 → **Top-5 内随机打乱**取一封（注入偶遇感，不总捞「最像」的）。

> 设计稿中的完整形态（三根滑杆、温度采样 softmax、ε-serendipity 保底、曝光预算 / 反霸屏 / 新信扶持、Redis 倒排桶）为**【演进】**，字段与机制见本节末。

### 3.3 递送：真实地理 → 车马速度【实现】

按 Haversine 距离分 5 档（`pickDeliveryTier`）：

| 距离 | 工具 | 基准时长 |
|---|---|---|
| < 20km | 徒步信使 | 4h |
| 20–200km | 马车 | 18h |
| 200–800km | 信鸽 | 36h |
| 800–2000km | 加急驿马 | 60h |
| > 2000km | 天涯专递（信天翁） | 96h |

- 笔友往来按 `baseHours × DELIVERY_HOURS_SCALE` 精算；**未知距离按 800km（信鸽档）兜底**，不落「徒步」误判。
- 信件入海无收件人、距离未知 → 固定短延时（`LETTER_POOL_DELAY_SECONDS`）。
- 设计稿中的 jitter / 里程文案 / 稀有递送掉落为**【演进】**。

### 3.4 公平性与空池兜底【实现·简化】

- 空池 → `OCEAN_EMPTY` 温和文案；冷启动靠**真人运营种子信**（署名「漂流邮局」，透明标注）+ 足量种子数据（`db:seed` 注入 6 位）。
- 设计稿的曝光预算 / 反热门疲劳 / 零曝光强保护为**【演进】**。

### 3.5 匹配相关数据与演进预留【演进】

- 演进字段（未建）：`mbti_confidence`（三档）、`mbti_test_score`（四维连续值）、`profile_vector`（pgvector）、`fishing_records.match_score`、雷同开场「行为指纹」降权。
- Redis 倒排桶（pool:geo / pool:interest / pool:mbti / pool:fresh）在有量后再上；MVP 起点为 PG 索引 + 应用层精排。

## 4. 内容安全与风控

> 核心思路：**以慢换准、分层裁决、高危即时**。所有 UGC（投递信、回信、笔友往来）先入审核，通过方可入池/送达。

### 4.1 审核流水线

**设计分层**：L0 客户端预过滤 → L1 机器初审（规则+分类，秒级阻断四类高危：涉政/诈骗/自残/联系方式）→ L2 大模型语义复审（可疑件，可吸收进递送窗）→ L3 人工复核（高危优先 ≤4h / 中危 ≤24h / 申诉独立）。

**当前实现【实现·简化】**：同步执行本地规则引擎（`moderation.rules.reviewText`），`ModerationProvider` 抽象支持 `MODERATION_PROVIDER=local|remote` 切换；`RemoteApiProvider` 为 **fail-closed 桩**（未配置/调用失败一律沿用本地结果，绝不返回 PASS 兜底）。调用点三处：投递（letters.submit）、回信（ocean.reply）、笔友往来（penpals.send）——**REVIEW 与 BLOCK 均拦截**（MVP 无人工队列，脏词/联系方式一律退回修改）。

审核记录落 `content_reviews` 表（脱敏：仅风险等级 / 动作 / 命中类别，不存原文）。

### 4.2 联系方式与不友善检测【实现】

- **归一化对抗还原**（`normalizeText`）：全角→半角、中文数字→阿拉伯数字、`at/艾特→@`、`dot→.`、数字间分隔符（空格/连字符/点）折叠。
- **联系方式模式**：长数字串、邮箱、URL、社交账号引流词（wechat/vx/telegram/whatsapp/line/ins…）。
- **多语种词库分桶**：zh / en 分桶存放，匹配时拍平。
- **定位认知（重要）**：联系方式禁令在对抗下**不可能 100% 执行**（谐音、emoji 替代、图片/手写号码、跨信件分段拼接）。护城河的真正定位 = **动机管理 + 经济成本 + 事后追责**，目标从「零泄漏」改为「可举报 + 可溯源 + 漏放后快速冻结」。图像 OCR、跨信件序列建模为**【演进】**。
- 命中处置：BLOCK（高危，含联系方式）记 WARNING 并自动升级；文案「漂流邮局不传递联系方式」，可修改后重投。

### 4.3 处置与风控阶梯【实现·简化】

- **自动处置**（`PenaltyService`，operator=AI）：
  - 内容命中 BLOCK → 记 1 条 `WARNING`（关联审核记录）；**累计 ≥3 → 自动 FREEZE 72h**。
  - 被举报：按 **distinct 举报人 ≥3** → 自动 FREEZE 待人工复核，并把相关待处理举报标记 `ACTIONED`。
  - 冻结幂等（仅冻结 ACTIVE）；冻结到期后登录/请求自动解冻。
- **请求期即时生效【实现】**：`JwtStrategy` 每次请求查库校验账号状态（BANNED / DELETED / FROZEN 未到期 → 403）；refresh 同样复核——存量 token 无法绕过封禁。
- **申诉**【实现·落表】：`POST /v1/appeals` 写入 `Appeal`（OPEN/UPHELD/OVERTURNED），人工裁决工作台为**【演进】**。
- 设计稿的「墨信值」信用分双轨、P0–P4 处置阶梯、静默降权为**【演进】**。

### 4.4 Grooming（诱导）专项【演进·设计保留】

> 注：年龄机制已取消（§5.1），下方「定向低龄 / 年龄不对称 / 未成年侧处置」类信号与合规动作在实现时需改为基于内容自述与行为推断；内容安全原则本身不变。

本质是**跨信件、跨时间的行为序列**（单封信常「看着没问题」）。识别信号（加权累计为风险分 G，0–100）：

| 信号类别 | 示例 | 权重 |
|---|---|---|
| 定向低龄 | 成年人持续定向与低龄账号通信 | 高 |
| 索取私密信息 | 索要真人照片（私密/裸露=**最高危**）、精确位置、学校、独处信息 | 高 |
| 孤立性话术 | 「加我别的号」「别告诉爸妈」「这是我们的秘密」 | 高 |
| 礼物/利益诱导 | 寄礼物/给钱/点卡换取照片、见面、联系方式 | 高 |
| 关系加速 | 短期迅速升温、过度赞美、性暗示渐进试探 | 中高 |
| 线下推进 | 任何约见、问地址、接送 | 零容忍 |
| 年龄不对称 | 年龄差大 + 上述任一 | 放大系数 |

阶梯：L0 观察（静默加权）→ L1 软干预（G≥30：向未成年侧插安全提示卡 + 转人工）→ L2 拦截+冻结接触（G≥60 或命中零容忍：拦截该信、冻结成年账号对未成年接触、≤4h 人工、按法域告知家长）→ L3 封禁+强制报告（确认 grooming/CSAM → 永封 + WORM 留证 + 按法域报告 NCMEC / Ofcom / 警方）。

**CSAM 红线**：任何疑似请求/暗示/传播 → 直接 L3 + 强制报告；**严禁主动留存影像本体**（哈希比对 + 即时移交）。

### 4.5 杀猪盘 / 情感诈骗【演进】

慢节奏长期书信是情感诈骗的最佳土壤，且其特征（高回信、长期深耕）与反海王漏斗相反。需**关系层建模**：金钱话术分类（投资/转账/虚拟货币/紧急汇款/礼品卡/带单/回本）→ 关系轨迹评分（模板化剧本复用聚类）→ 反诈提示卡 + P2 冻结 + 关联清剿。

### 4.6 自残 / 心理危机（E 类）【演进·设计保留】

**原则：危机内容不作为「违规」惩罚发信人**，区分「自身危机」（关怀：不拦截账号、危机关怀层 + 本地 24h 热线 + 高风险升级人工、未成年人按法域告知监护人）与「鼓动/教唆他人自残」（高危违规处置）。

本地热线表（按用户声明居住地展示，**季度复核**）：
- 香港：撒玛利亚会 2896 0000 / 2389 2222；生命热线 2382 0000；Open Up（青少年在线）9101 2012。
- 台湾：安心专线 1925；生命线 1995；张老师 1980；紧急 110/119。
- 英国：Samaritans 116 123；紧急 999。欧盟通用紧急 112。美国：988；紧急 911。
- 兜底：findahelpline.com。

### 4.7 举报 / 拉黑 / 隐身 / 申诉闭环【实现】

- 一键举报（分类）+ 同步拉黑 + 隐身；对对方**不暴露触发者身份与时点**（反报复）。
- **拉黑**：双向不可见、不可匹配、不可结缘/发信（`blockedUserIds` 在打捞召回、回信结缘、笔友发信三处硬过滤）。
- **隐身（闭关）**：不被投递/被打捞（召回侧过滤）；本人仍可打捞。
- **举报处置**：自动风控（见 4.3）+ 人工队列【演进】；商店硬门槛「举报 + 拉黑 + 24h 内处置冒犯内容 + 屏蔽涉事用户」四件套在 MVP 内。
- 陌生人资料接口对无关系者返回 404（不区分「不存在/无权」，防枚举探测）。

## 5. 合规与数据保护

### 5.1 年龄机制：已取消（2026-10-03 产品决策）

**决定**：不设年龄分层机制——注册不采集出生日期，匹配池对全体用户统一，不做守护模式 / 同龄池隔离 / 年龄保障（Age Assurance）/ 家长同意（VPC）。

**执行**：`ageTier` / `birthDate` / `guardianMode` 字段、`parental_consents` 表、`AgeTier` / `ConsentStatus` 枚举与全部相关逻辑已从代码与数据库移除（迁移 `20261003120000_remove_age_mechanism`）；注册仅需邮箱 + 密码 + 笔名。

**取舍（自担·已知风险）**：失去「未成年隔离 + 家长同意」防线后，应用商店分级问卷、GDPR-K / COPPA 类儿童数据规则、UK OSA 式年龄保障要求将缺少制度化缓冲；若未来重新引入年龄分层，需按破坏性变更流程（两步发布）恢复表结构与召回侧隔离。**内容安全体系（第 4 章，含 grooming 检测与危机干预）不受影响**，仍对全体用户生效。

### 5.2 合规矩阵（要点精简）

> 正式上线前须经目标辖区持牌律师复核（未成年人保护 / 数据出境 / AI 标识三项）。**注：因已取消年龄机制（见 5.1），各辖区「未成年人/儿童」条款目前无制度化落地，属已知取舍。**

- **香港 PDPO**：六项保护原则；注册收集中英文《收集个人资料声明》（PICS）；直接促销须明确同意 + 免费拒绝渠道；可快速处置「起底」内容（投诉+下架机制）；儿童资料加倍审慎。
- **台湾 個資法**：蒐集前告知义务（§8）；特定目的 + 法定事由；当事人查询/更正/停止/删除权不可预先抛弃；未成年人（<18）法律行为须法定代理人同意；国际传输受限可能（§21）。
- **欧盟 GDPR + GDPR-K**：逐处理活动映射合法基础（合同必要/同意/合法利益）；儿童数字同意线成员 13–16（工程取 **16 高水位**）；**DPIA 强制**（涉未成年 + 自动化匹配/审核）；数据出境须 SCC + 评估；EU 代表（Art.27）。
- **美国 COPPA + CCPA/CPRA**：COPPA 以「实际知晓 <13」为触发——年龄硬拦已取消（见 5.1），须格外注意儿童涌入风险；13–16 的「出售/共享」须 opt-in；其他州隐私法逐步跟进。
- **商店政策**：Apple 5.1.4 / Google Families + UGC 四件套（举报/拉黑/24h 处置/屏蔽）；年龄分级问卷与隐私标签如实填写——**UGC + 陌生人社交是拒审重灾区**。

## 6. 数据模型与 API

### 6.1 数据模型【实现】

**权威来源 = `apps/api/prisma/schema.prisma`**（17 表 / 13 枚举 / 5 个迁移），本节省略 DDL。

| 域 | 表 | 一句话 |
|---|---|---|
| 账号 | `users` / `user_profiles` | 账号（状态）；名片（MBTI/兴趣/滑杆/geohash5/隐身） |
| 信件 | `letters` / `preview_snapshots` / `fishing_records` / `unseal_records` | 状态机主体（version 乐观锁）；去人格化预览快照；打捞（唯一 `[userId,letterId]` + 预览锁）；拆封（7 天 deadline / warnedAt / recycledAt） |
| 笔友 | `pen_pal_relations` / `correspondences` | 关系（唯一对 + status/intimacy）；往来（`deliverAt/deliveredAt` 在途） |
| 递送 | `delivery_tasks` | DB 镜像（**当前无读写方**，为 MQ 演进预留） |
| 配额 | `daily_quotas` | 唯一 `[userId,date]`，原子扣减 |
| 审核安防 | `content_reviews` / `penalties` / `reports` / `blocks` / `appeals` | 审核留痕；处罚；举报（distinct 计数）；拉黑；申诉 |
| 隐私 | `data_deletion_requests` / `notifications` | 注销请求（执行器推进）；去人格化通知 |

**关键约定**：

- **无「已读」类字段**；**无精确经纬度**（仅 `geohash5`，±2.4km）。
- **索引策略**：召回主路径 `letters(status, poolVisibleAt)`；巡检 `(status, expireAt)`、`fishing_records(released, lockUntil)`、`correspondences(deliveredAt, deliverAt)`；双向查询 `blocks(targetUserId)`、`pen_pal_relations(userBId)`；`reports(reporterId)`。
- **迁移原则**：只增不改（additive）；新增非空列必须「可空 → 回填 → SET NOT NULL」三步（见 `penalties.publicId` 迁移范例）；破坏性变更为【演进】前走两步发布。
- 枚举与 shared 双向同步由 `enum-drift.spec.ts` 守护（当前覆盖 9 个有孪生的枚举）。
- PostGIS / pgvector 未启用（MVP 用 GeoHash 前缀 + 应用层精排）。

### 6.2 API 约定

**前缀与鉴权【实现】**：统一 `/v1`；全局 JWT 守卫（`@Public()` 例外：health、auth）；`Authorization: Bearer <access>`（默认 15m）+ `POST /v1/auth/token/refresh`（默认 30d，**仅接受 refresh 类型令牌且复核账号状态**，冻结/封禁/注销即时失效）。生产强制强随机 `JWT_SECRET`（否则拒绝启动）。

**响应格式【实现】**：以代码为准——

```jsonc
// 成功
{ "ok": true, "data": { ... } }
// 失败
{ "ok": false, "error": { "code": "OCEAN_EMPTY", "message": "此刻海面很平静…" } }
```

- **错误码为字符串枚举**（如 `QUOTA_EXHAUSTED` / `UNSEAL_BUSY` / `ACCOUNT_FROZEN`），非设计稿的五位数字码；`message` 即可直接展示的世界观文案。
- 设计稿的 `{code,message,data,meta}` 信封与 `Idempotency-Key` 幂等头**未采用**（【演进】按需引入）；列表分页：通知用游标，其余为有界小列表。
- **去人格化约定【实现】**：不返回在线/已读/最后活跃/精确位置；距离为模糊文案；打捞者身份不外泄。

### 6.4 实时事件（WebSocket）【演进】

现为**前端 45s 轮询**（`useNotifications`）+ 服务端 scheduler 埋点。设计的目标事件集（仅「抵达类」，不破坏慢与去人格化）：

| event | 触发 | 去人格化约束 |
|---|---|---|
| `letter.delivered` | 投递的信漂入海面 | 不含打捞者信息 |
| `letter.fished` | 自己的信被人拾起 | **不透露**打捞者身份 |
| `penpal.reply_arrived` | 笔友回信经在途后抵达 | 不含 read/在线 |
| `unseal.reply_window_warning` | 回信窗口剩 ≤1 天 | — |
| `unseal.expired_redrift` | 7 天未回信，信回池 | 温和文案 |
| `paired.success` | 回信成功结缘（双方） | 名片去人格化 |

接入时保持「降级回轮询」的客户端策略。

## 7. 技术架构与工程实践【实现】

### 7.1 技术栈

| 层 | 选型 |
|---|---|
| 前端 `apps/web` | Nuxt 3.13.2（SPA、移动优先）+ Pinia + UnoCSS + GSAP + `@vite-pwa/nuxt`（可安装 + SW 离线壳） |
| 后端 `apps/api` | NestJS 10 + Prisma 5 + PostgreSQL 16 + Redis 7 + `@nestjs/schedule`（时间驱动）+ `@nestjs/throttler`（限流） |
| 共享 `packages/shared` | 枚举 / 常量 / 类型 / MBTI 相容算法 / 时间工具 |
| 工程 | pnpm workspace 单仓；Node ≥20（CI 与镜像用 22）；Vitest；GitHub Actions |

设计稿中 Go/RabbitMQ/PostGIS/pgvector/对象存储为**【演进】**，MVP 一律不上以避免过度设计（真正的形态是「低频异步状态机」，不是高并发 IM）。

### 7.2 模块结构

- **后端 12 模块**：auth / users / letters / ocean（打捞）/ penpals / quota / delivery（调度）/ moderation / penalty / reports / notifications / health；`common/`（Prisma、Redis、geohash、守卫、过滤器、拦截器）。
- **前端**：`pages/`（登录 / 引导 / 漂流海 / 我的信件 / 笔友信匣 / 我的 / 通知 / 设置 / 公开名片）、`components/`、`stores/`（auth/quota/ocean）、`composables/`（useApi/useToast/useNotifications）、`mocks/`（内存假后端，开发态默认开启）。
- **前后端共享**：`packages/shared` 为单一事实来源（枚举、节奏常量、MBTI 算法、类型）。

### 7.3 并发与一致性

- **拆封三闸**：Redis 原子锁（`SET NX EX` + Lua 比对删除）→ DB 条件更新（`WHERE status=HOOKED` CAS，互斥的真正裁决）→ `version` 审计。任一失败退还配额。Redis 异常同样退还配额（不静默吞额度）。
- **调度幂等**：所有流转「先读 DB → 条件更新 → 仅 `count===1` 发通知」；窗口预警用 `warnedAt`、回收用 `recycledAt` 去重。
- **配额**：`daily_quotas` 唯一 `[userId,date]` + 条件更新原子扣减（`gt:0`）/ 退还（`lt:cap` clamp）。
- **回信-回池竞态**：`reply` 事务内条件更新 `SEALED_OPEN→PAIRED`，`count===0` 抛错回滚，杜绝「已回池的信被复活」。
- **限流**：全局 300/min·IP + `/v1/auth/*` 8/min·IP；反代后按真实 IP（`trust proxy=1`）。
- **注意**：限流计数当前为**进程内内存**，api 多副本会静默放大上限（见 §8.7）。

### 7.4 配置与密钥

- 运行时配置集中在 `apps/api/src/config/configuration.ts`（可 env 覆盖）：配额、节奏（预览锁/回信窗口/漂流上限/回池次数）、投递延时与缩放（`DELIVERY_HOURS_SCALE`）、审核 Provider、限流。
- **生产安全强制【实现】**：`NODE_ENV=production` 时 `JWT_SECRET` 缺失 / 默认值 / 长度 <32 → **拒绝启动**。
- 前端 API 基址与 Mock 开关为**构建期固化**：`NUXT_PUBLIC_API_BASE=/v1`、`NUXT_PUBLIC_USE_MOCK=0`（改需重建镜像）。

### 7.5 测试与 CI

- **单测**（`pnpm test`，零基建）：Vitest，覆盖纯逻辑（MBTI/递送分档/geohash/审核归一化/摘录/打捞打分/时间工具）+ service 回归（删号执行器/配额/打捞/回信竞态/枚举防漂移）。
- **集成 / e2e**（`pnpm test:integration`，需 PG+Redis）：全链路 letter-loop、并发（拆封唯一/配额原子/打捞认领）、scheduler 六分支、通知、风控（冻结即时生效 / refresh 失效 / GDPR 注销全链路）、限流；每例 `TRUNCATE + flushdb` 隔离；**安全闸：DATABASE_URL 库名必须含 "test"**（解析 URL 精确校验，防误清非测试库）。本地零配置：`docker compose up -d` + 一次性 `createdb inkling_test` 后，直接 `pnpm test:integration`（自动派生测试库并对其应用迁移）。
- **CI 三档**：`unit`（api+web typecheck + 单测）｜`integration`（GitHub `services:` 免费 PG16+Redis7）｜`images`（离线验证两镜像可构建）。

### 7.6 已知技术约束

| 约束 | 说明 |
|---|---|
| api 必须单副本 | 进程内轮询调度 + 启动时迁移 + 内存限流；多副本需先做 leader 选举 / 独立迁移 Job / Redis 限流存储 |
| 时间驱动精度 | 20s 轮询（最终一致），秒级叫醒需 MQ |
| 镜像偏大 | api 镜像保留完整依赖（便于容器内跑 migrate/seed），瘦身属优化期 |
| GDPR 导出 | 现为接口内联 JSON，大体量期改异步打包 |

## 8. 部署与运维（runbook）

> 目标读者：上线执行人。**本手册与产物在无云环境下离线编写**，首次构建以 CI 的 Images 工作流为绿色门禁；真机首跑若有镜像层细节按报错微调即可。

### 8.1 拓扑

单机一台（2C4G 起步），四个容器，**Caddy 做边缘**：自动 HTTPS + 托管前端静态 + 把 `/v1/*` 同源反代给后端（前端因此零 CORS）。

```
Internet → caddy(:443 自动 HTTPS)
              ├─ /v1/*  → api:3001（NestJS；启动时 prisma migrate deploy → node dist/main.js；不对外暴露）
              │              └→ postgres:5432 / redis:6379（命名卷持久化）
              └─ 其余    → /srv 静态产物（SPA history 回退 index.html）
```

配套产物：`deploy/{api,web}.Dockerfile`、`deploy/Caddyfile`、`deploy/docker-compose.prod.yml`、`deploy/env.production.example`、`.dockerignore`、`.github/workflows/images.yml`。

> ⚠️ Caddyfile 必须用**互斥 `handle` 块**分隔 API 与 SPA（`try_files` 在 Caddy 默认指令顺序中先于 `reverse_proxy`，裸写会把 `/v1/*` 重写为 index.html）。已修复并附安全响应头与 JSON 访问日志。

### 8.2 服务器选型

| 项 | 建议 |
|---|---|
| 规格 | 2C4G / 60G SSD（更稳 2C8G） |
| 系统 | Ubuntu 22.04 LTS；Docker Engine + Compose v2 |
| 节点 | 香港 / 新加坡（海外华人/留学生，延迟与合规均衡） |
| 网络 | 开放 80/443；22 仅限管理 IP；域名 A 记录先生效（Caddy 签证书依赖） |

### 8.3 环境变量与密钥（要点）

`cp deploy/env.production.example .env` 后逐项填写。关键项：

| 变量 | 要点 |
|---|---|
| `SITE_ADDRESS` | 正式域名（自动 HTTPS）；本机联测填 `:80` |
| `POSTGRES_PASSWORD` / `DATABASE_URL` | 强随机且一致；host 用服务名 `postgres`（非 localhost） |
| `REDIS_URL` | `redis://redis:6379` |
| `JWT_SECRET` | `openssl rand -base64 48`；**生产缺失/默认值会拒绝启动** |
| `DELIVERY_HOURS_SCALE` | **必须 1**（真实 4–96h 慢递送；0 会秒达破坏核心体验） |
| `THROTTLE_*` | 默认 300/min；**生产勿设 `THROTTLE_DISABLED=1`** |
| `SEED_PASSWORD` / `ALLOW_SEED` | seed 默认密码可覆盖；生产执行 seed 需显式 `ALLOW_SEED=1` |

前端三个值构建期固化（见 §7.4）。`.env` 已被 gitignore，绝不提交。

### 8.4 首次部署

```bash
git clone <repo> inkling && cd inkling
cp deploy/env.production.example .env && vim .env        # 填完所有 CHANGE_ME
dig <域名>                                                # 确认 A 记录已生效
docker compose -f deploy/docker-compose.prod.yml --env-file .env up -d --build
# api 启动时自动 prisma migrate deploy（首次套用全部 4 个 migration）
docker compose -f deploy/docker-compose.prod.yml --env-file .env exec api pnpm prisma:seed   # 一次性（见 §8.10 检查项）
curl -fsS https://<域名>/v1/health && curl -fsS https://<域名>/v1/health/ready
```

### 8.5 健康探针

| 端点 | 语义 |
|---|---|
| `GET /v1/health` | 存活（进程在跑即 200，不查依赖） |
| `GET /v1/health/ready` | 就绪（DB + Redis 均可用才 200，否则 503） |

api 容器 `HEALTHCHECK` 使用 `/v1/health/ready`；caddy 依赖 api `service_healthy` 后启动。外部 Uptime 探 `/v1/health`。

### 8.6 备份与恢复

数据全在两个命名卷：`pg-data`（**权威**）、`redis-data`（可重建，非权威）——**只有 Postgres 必须备份**。

```bash
# 每日 03:30 备份、保留 14 天（host crontab）
30 3 * * * root cd /opt/inkling && docker compose -f deploy/docker-compose.prod.yml --env-file .env exec -T postgres \
  pg_dump -U inkling inkling | gzip > /opt/inkling/backups/inkling-$(date +\%F).sql.gz \
  && find /opt/inkling/backups -name 'inkling-*.sql.gz' -mtime +14 -delete
```

上线前**务必演练一次恢复**（恢复到测试库验证）。异地同步对象存储为**【演进】**。

### 8.7 伸缩与已知约束（重要）

| 约束 | 何时处理 |
|---|---|
| **api 必须单副本**（进程内调度 + 启动时迁移 + 内存限流） | 横向扩前：scheduler 抽独立 worker / 迁移改一次性 Job / 限流接 Redis storage |
| Redis 单实例（仅锁/计数） | 高可用期上 Sentinel/集群 |
| 镜像偏大（含 devDeps 以便 migrate/seed） | 优化期 `pnpm deploy --prod` 瘦身 |
| GDPR 导出内联 JSON | 大体量期改异步打包 + 对象存储 |

### 8.8 升级 / 发布流程

```bash
cd /opt/inkling && git pull
docker compose -f deploy/docker-compose.prod.yml --env-file .env up -d --build
# 仅重建变更镜像；api 重启时自动套用新增 additive migration
```

- **数据库变更原则**：只增不改（加表/列/索引）；新增列给默认值或可空，保证「旧代码 + 新表结构」兼容。
- 破坏性变更走两步发布（先兼容 → 再清理）；**严禁单步删除在用字段**。
- 迁移文件一旦发布不再修改（修改已应用的迁移会导致校验和漂移；本地开发库需 `prisma migrate reset`）。

### 8.9 回滚预案

```
出问题 → 本次仅 additive 迁移？
  ├─ 是 → A. 代码级回滚：git checkout 上一 tag → up -d --build（新表/列对旧代码无害）
  └─ 否 → B. 代码 + 数据回滚：先 stop api 止血 → 恢复发布前 pg_dump → 回滚代码 → 验活
C. 紧急全停：docker compose down（保留命名卷；**绝不加 -v**，那会删数据）
```

**回滚前置**：破坏性发布前已备份 + 已演练恢复 + 镜像可回退（给镜像打 git sha tag，而非只用 latest）。

### 8.11 故障排查

| 现象 | 处理 |
|---|---|
| Caddy 签不出证书 | DNS 未生效 / 80 被占 / `SITE_ADDRESS` 写成 `:80`；`logs caddy` 看 ACME |

## 9. 风险、决策与待办

### 9.1 结构性风险（做再美也可能致命）

| 风险 | 要点与对策 |
|---|---|
| **冷启动死亡螺旋** | 按地理+MBTI+兴趣分桶后小基数池≈空；回信侧兜不住。对策：**单点高密度封闭冷启动**（一个社群做到「本地活信 ≥ 阈值 且 新用户 7 天首次结友率 ≥ 阈值」再开第二个点），密度未达标前不投放拉新 |
| **「慢」vs 留存** | 正反馈最长 10 天+；从一开始就按「低频高价值订阅 + 收藏付费」建模并写入共识，不走 DAU/广告；新手前 7 天制造一次确定性早期成功 |
| **性别供需失衡** | 女性保护性限流 + 更高分发权重（鼓励供给）、上线即拉黑/隐身/举报、冷启动控初始性别比 ≈1:1 |
| **导流到站外** | 检测不可能封死；靠「站内关系增值」（专属信纸/在途仪式/信缘博物馆【演进】）降低动机；KPI 从「零导流」改为「关系站内存续深度」 |
| **合规红线** | 数据出境是上线门禁（§5.4），不达标 = No-Go；年龄机制已取消（§5.1，风险自担） |
| **杀猪盘** | 与反海王漏斗方向相反，需独立的关系层风控（§4.5） |

### 9.2 已拍板决策（摘要）

- 目标市场 = **海外/港台**（不走国内备案；对齐 PDPO/個資法/GDPR/COPPA）。
- 年龄 = **不做年龄分层**（2026-10-03 拍板）：注册不采集出生日期、匹配池统一；原「13+ 硬门控 + 守护模式」已全部移除（见 §5.1）。
- MBTI = **自报型号**（不强制测评；未知合法）。
- **回信窗口 7 天自「送达拆封者」起算，回信在途不计入对方窗口**（远距离不误伤）。
- **审核双轨**：高危秒级同步先行，低风险件才可吸收进递送窗；**藏头玩法无审核豁免**。
- **不做**：AI 暖场信（用真人运营种子信）、成笔友奖励额外拆封券、公开排行榜、卖次数/概率/优势；增长钩子仅保留可选的对外分享。
- 因服务器成本：**暂不租云**，先走「零基建 + 本机 Docker」全免费联调；生产预案提前离线就绪（C 档）。

### 9.3 演进优先级

1. **阶段二（粘性）**：装扮系统 + 信手礼收藏 + 关系仪式（信缘博物馆/告别信）。
2. **阶段三（精度）**：pgvector 向量召回 + 偏好滑杆全套 + 真实距离/稀有递送。
3. **阶段四（生态）**：城市文旅联名 + 季节活动 + 公开信展。
4. **C 档（需付费/真机）**：云部署首跑、第三方多语种审核 API、Web Push/WebSocket、对象存储。
