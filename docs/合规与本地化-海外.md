# 《信逢 Inkling 海外/港台合规与本地化方案》

> 版本：v1.0 ｜ 日期：2026-06-14 ｜ 阶段：细化设计（上线前）
> 适用：海外/港台市场（不走国内备案）｜ 全年龄（含未成年人）｜ 慢社交陌生人书信 PWA
> 性质：本文为产品合规设计框架，非正式法律意见。正式上线前须经各目标辖区持牌律师复核（尤其未成年人保护、数据出境、AI 标识三项）。

## 1. 司法辖区合规矩阵

### 1.1 辖区适用判定原则

采用「用户所在地法 + 平台分发地法」叠加：用户注册时声明的居住地 / IP / 商店账户区域共同决定适用法规集合。**首发建议优先级**：港台（中文母市场，法规相对清晰）→ 新加坡/马来西亚华语区 → 欧盟（GDPR 最严，作为合规上限基线）→ 美国（COPPA 风险最高，建议谨慎评估后进入）。

### 1.2 逐辖区义务矩阵

#### A. 香港《个人资料（私隐）条例》PDPO（Cap. 486）

| 义务项 | 具体要求 | 优先级 |
|---|---|---|
| 六项保护资料原则（DPP1–6） | 收集须合法公平且告知目的；准确并按需保存；仅按声明目的使用；采取保安措施；公开私隐政策；容许查阅及更正 | 🔴 |
| 收集声明（PICS, DPP1） | 注册时以中英文展示《收集个人资料声明》，列明目的、转移对象类别、查阅更正权利 | 🔴 |
| 直接促销（第6A部） | 推送 / 营销前须取得明确同意并提供「免费拒绝」渠道，违规可刑事入罪 | 🟡 |
| 跨境转移（s.33） | s.33 尚未生效，但 PCPD 强烈建议遵守《跨境资料转移指引》；境外大模型审核须做转移影响评估 | 🟡 |
| 起底罪行（2021修订 s.64） | 平台须能快速处置「未经同意披露他人个人资料」的内容（起底）；设投诉与下架机制 | 🔴 |
| 资料外泄通报 | 现为建议性，PCPD 拟立法强制；MVP 即建立外泄应急流程 | 🟡 |
| 未成年人 | PDPO 未单设儿童条款，但 PCPD 指引要求对儿童资料加倍审慎；与 GDPR-K 对齐处理 | 🔴 |

#### B. 台湾《個人資料保護法》（個資法）

| 义务项 | 具体要求 | 优先级 |
|---|---|---|
| 告知义务（§8） | 蒐集前告知：蒐集者、目的、个资类别、利用期间/地区/对象/方式、当事人权利 | 🔴 |
| 同意与目的拘束（§5、§19、§20） | 须有特定目的及法定事由（同意/契约必要）；利用不得逾越目的必要范围 | 🔴 |
| 当事人权利（§3） | 查询、阅览、复制、补充更正、停止蒐集处理利用、删除——不得预先抛弃 | 🔴 |
| 国际传输（§21） | 主管机关得限制特定国家的跨境传输；境外大模型审核须评估并在政策披露 | 🟡 |
| 安全维护（§27） | 采取适当安全措施防止个资被窃取/窜改/泄露 | 🔴 |
| 敏感个资（§6） | 健康、性生活等特种个资原则禁止蒐集——书信内容可能涉及，须在审核与存储上特别处理 | 🟡 |
| 未成年人 | 民法上未成年人（未满18，2023年下修成年为18岁）法律行为须法定代理人同意 | 🔴 |
| 违规罚则 | 行政罚 + 刑责（意图营利非法利用可处徒刑）；公务/非公务机关均受规范 | — |

#### C. 欧盟 GDPR + GDPR-K（未成年）

| 义务项 | 具体要求 | 优先级 |
|---|---|---|
| 合法性基础（Art.6） | 每类处理须有合法基础：同意 / 合同必要 / 合法利益（须做 LIA 衡平） | 🔴 |
| 透明告知（Art.13–14） | 分层隐私政策，含数据类别、目的、基础、留存、第三方、跨境、用户权利 | 🔴 |
| 数据主体权利（Art.15–22） | 访问、更正、删除（被遗忘）、限制、可携、反对、免于自动化决策 | 🔴 |
| **GDPR-K（Art.8）** | **信息社会服务对儿童的同意：默认数字同意年龄 16，成员国可下调至 13；低于该龄须经家长同意并「尽合理努力核实」** | 🔴 |
| 设计与默认隐私（Art.25） | Privacy by Design/Default：未成年默认最严设置（守护模式） | 🔴 |
| DPIA（Art.35） | 大规模处理 + 系统性监控 + 涉未成年 + 自动化匹配/审核 → **强制做 DPIA** | 🔴 |
| 数据出境（Art.44–49） | 传至第三国须 SCC / 充分性认定 / 适当保障；境外大模型审核为关键评估点 | 🔴 |
| EU 代表（Art.27） | 无欧盟实体但面向欧盟用户，须指定欧盟境内代表 | 🟡 |
| 违规罚则 | 最高 2000 万欧元或全球营业额 4% | — |

> **GDPR-K 各国数字同意年龄差异**：爱尔兰/荷兰=16，法国=15，西班牙/比利时/丹麦=13，德国=16，意大利=14。MVP 工程上以「16 作为统一高水位线」最省事——低于 16 即触发家长同意流程，覆盖全部成员国。

#### D. 美国 COPPA（<13）+ CCPA/CPRA

| 义务项 | 具体要求 | 优先级 |
|---|---|---|
| **COPPA 适用判定** | 面向 <13 儿童或「实际知悉」用户 <13 即适用，要求**可验证家长同意（VPC）** 后方可收集 | 🔴（决定是否进美国市场） |
| VPC 方式 | 信用卡验证、政府证件、视频面谈、签名表单等——成本高、体验重 | 🔴 |
| COPPA 安全港 | 数据最小化、家长查看/删除权、禁止以提供过多个资为参与条件 | 🔴 |
| CCPA/CPRA（加州） | 知情权、删除权、更正权、退出「出售/共享」、敏感个资限用；达门槛才适用 | 🟡 |
| 未成年「出售」 | CPRA 下 13–16 岁须 opt-in 才可「出售/共享」，<13 须家长 opt-in | 🟡 |
| 其他州 | VA/CO/CT/UT/TX 等州综合隐私法陆续生效，多含未成年特别条款 | 🟢 |

> **战略建议（强）**：COPPA 的 VPC 成本与法律风险极高（FTC 罚款案例频发）。**MVP 美国市场建议「年龄门控为 13+」**——即明确不向 <13 提供服务、注册即拦截，从而规避 COPPA 的 VPC 重负担；13–17 岁按未成年守护模式 + CCPA/CPRA 未成年条款处理。若坚持服务 <13，则 VPC 必须先落地，否则不得进入美国。

#### E. App Store / Google Play / Web 平台政策

| 平台 | 关键要求 | 优先级 |
|---|---|---|
| Apple App Store | 5.1.4 儿童数据；UGC（1.2）须有：内容过滤、举报机制、屏蔽用户能力、24h 内处理冒犯内容并移除发布者的承诺；年龄分级问卷如实填写；陌生人社交需明确风险提示 | 🔴 |
| Apple 隐私 | 隐私营养标签（Privacy Nutrition Label）、ATT（如有跨 App 追踪）、隐私政策链接 | 🔴 |
| Apple 未成年 | Declared Age Range API / Kids Category 政策；不得将儿童数据用于广告定向 | 🟡 |
| Google Play | UGC 政策同样要求举报+屏蔽+审核；Families 政策；Data Safety 表单 | 🔴 |
| Google 未成年 | 「Teacher Approved」/ 目标受众与内容政策，须声明目标年龄段 | 🟡 |
| Web/PWA | 不受商店审核但仍受各地法律约束；Cookie 同意（ePrivacy）、可访问性建议 | 🟡 |

> **关键提醒**：UGC + 陌生人社交是 App Store/Play 拒审重灾区。**「举报 + 拉黑 + 24 小时内处置冒犯内容 + 屏蔽涉事用户」四件套是商店硬门槛**，必须在 MVP 完成，否则上不了架。书信本质即 UGC。

## 2. 数据保护落地

### 2.1 合法性基础与同意管理 🔴

**分处理活动映射合法基础**：

| 处理活动 | GDPR 合法基础 | 港台对应 |
|---|---|---|
| 账户注册、投递/打捞/拆封核心功能 | 合同必要（Art.6(1)(b)） | 契约必要 |
| 地理就近匹配（GeoHash5） | 同意 + 合同必要 | 同意 |
| AI 内容审核（含境外模型） | 合法利益（安全）+ 法律义务 | 合法事由/同意 |
| MBTI/兴趣画像匹配 | 同意 | 同意 |
| 营销推送 | 同意（opt-in） | 明确同意 |
| 未成年用户全部处理 | **家长同意 + 上述基础** | 法定代理人同意 |

**同意管理要点**：
- 颗粒化同意：核心功能、画像匹配、营销分开勾选，不捆绑。
- 同意可撤回，撤回与给予一样容易（设置内一键关闭）。
- 同意日志：记录同意版本、时间戳、文本快照、IP 哈希——举证用。

**未成年家长同意流程（🔴 MVP 必须）**：
1. 年龄声明 → 命中阈值（EU<16、台<18、US 拦<13）→ 进入家长同意分支。
2. 家长同意核实方式分级（MVP 务实方案）：
   - **MVP 最低**：家长邮箱验证 + 声明确认（GDPR「合理努力」下限，配合低数据收集可接受）。
   - **进阶（🟢）**：信用卡小额验证 / 政府证件（COPPA VPC 级别，仅在确需服务 <13 时上）。
3. 未成年账户默认开启**守护模式**：默认隐身、严格内容过滤、限制陌生匹配频率、禁用任何线下见面引导、家长可查看/删除数据。

### 2.2 数据最小化 🔴

产品设计已内建强最小化，应固化为合规卖点：

- **地理**：只存 GeoHash 前 5 位（±2.4km），原始经纬度内存即弃不落库 —— ✅ 文档化为隐私设计证据，写入 DPIA。
- **不显示「已读」、打捞预览不露真人照片** —— 符合数据最小化与未成年保护。
- 注册仅收集功能必需字段；MBTI 自报、兴趣标签均为可选/可空（「未知」型号合法存在）。
- 书信内容可能含敏感个资（健康/性/政治/宗教）——审核管线对敏感类别做特殊标记与最短留存。

### 2.3 数据驻留与跨境传输（境外大模型审核出境评估）🔴

**这是本项目最关键的合规风险点。** AI 审核若调用境外大模型（如海外 API），书信内容（可能含个资/敏感个资）将出境。

**评估与缓解措施**：

| 措施 | 说明 | 优先级 |
|---|---|---|
| 传输影响评估（TIA/转移评估） | 针对每个出境模型供应商做评估，记录目的国法律、政府调取风险 | 🔴 |
| SCC + 补充措施 | 与模型供应商签欧盟标准合同条款；加密传输 | 🔴 |
| **审核前最小化/假名化** | 审核仅传必要文本；剥离/掩码可识别身份字段（姓名、联系方式、精确地址）后再出境 | 🔴 |
| 不持久化于供应商 | 选择「不留存、不训练」的企业级模型条款（zero-retention） | 🔴 |
| 区域化部署（演进） | 欧盟用户优先用欧盟区模型端点；港台/亚洲用户用亚洲区端点 | 🟢 |
| 同意/告知 | 隐私政策明确披露「为内容安全，文本将经境外 AI 服务处理」 | 🔴 |
| 台湾 §21 / 港跨境指引 | 留意主管机关对特定国家的限制清单 | 🟡 |

> **务实建议**：MVP 阶段若用境外模型，**务必启用 zero-retention 企业条款 + 出境前 PII 掩码**，并在 DPIA / 转移评估中留痕。若供应商无法保证不训练/不留存，则不得用于未成年用户内容。

### 2.4 留存期限 🟡

| 数据类型 | 建议留存 | 依据 |
|---|---|---|
| 草稿/未投递信件 | 用户删除即删，最长 30 天 | 最小化 |
| 漂流海/在途信件 | 状态机生命周期内 + 回池逻辑所需 | 功能必要 |
| 已成笔友信匣 | 关系存续期间 + 账户注销后 30 天清除 | 合同 |
| AI 审核记录/命中日志 | 6–12 个月（安全与申诉举证） | 合法利益 |
| 同意/年龄声明日志 | 账户存续 + 注销后保留合理举证期 | 举证义务 |
| 举报/封禁记录 | 12–24 个月（应对执法/复发） | 安全义务 |
| 账户注销 | 主动删除 + 软删除冷却期（防滥用）后硬删除 | 被遗忘权 |

### 2.5 被遗忘权 / 数据可携权 🔴

- **删除权**：设置内「注销账户」→ 触发删除流水线（信件、画像、日志按上表分级处理；法律须留存项匿名化）。未成年额外允许家长发起删除。
- **可携权**：导出用户书信与资料为结构化格式（JSON/可读 PDF）。MVP 可先做「邮件申请 + 人工导出」🟡，自助导出按钮进演进 🟢。

### 2.6 隐私政策与用户协议要点 🔴

必含模块（中英 + 繁简）：
1. 数据控制者身份与联系方式（及 EU 代表、DPO/联系人）。
2. 收集的数据类别（含 GeoHash、画像、书信内容）。
3. 每类处理目的与合法基础。
4. **境外 AI 审核与跨境传输披露**。
5. 留存期限。
6. 用户权利与行使方式（删除/查阅/可携/反对/撤回同意）。
7. **未成年人专章**：家长同意、守护模式、家长权利。
8. 第三方（模型供应商、对象存储、推送服务）。
9. Cookie/本地存储说明。
10. 投诉渠道与监管机构指引（PCPD / 台个资主管机关 / 各国 DPA）。

用户协议（ToS）须含：禁止行为（骚扰、起底、诈骗、引流、未成年不当接触）、UGC 许可、举报与处置规则、线下见面免责与风险提示、账户封禁与申诉。

## 3. 内容与 AI 合规

### 3.1 AI 生成内容标识义务 🟡（部分 🔴）

| 辖区 | 要求 | 优先级 |
|---|---|---|
| 欧盟 AI Act | 与 AI 交互须告知用户；AI 生成/操纵内容须可识别标记（透明度义务，分阶段生效） | 🟡 |
| 中国大陆 | 不适用（不走国内市场），但若内容回流需注意——本项目不涉 | — |
| 港台 | 暂无强制 AI 标识法，遵循平台政策与诚信原则 | 🟢 |
| 平台 | Apple/Google 要求披露 AI 生成功能 | 🟡 |

**本项目落点**：
- 若有「AI 暖场信」「AI 辅助润色」等功能，**必须标识「由 AI 生成/辅助」**，不得伪装成真人笔友。🔴（涉欺骗与未成年保护）
- AI 审核本身属内部安全处理，无需对外标识，但隐私政策须披露其存在。

### 3.2 内容审核记录留存 🔴

- 审核管线对每封信记录：审核结论、命中规则/类别、置信度、时间、是否人工复核、处置动作。
- 留存 6–12 个月，供申诉、执法配合、平台审计。
- 高危拦截（自残、儿童性剥削 CSAM、暴力、诈骗、联系方式引流）须单独标记并触发处置。
- **CSAM 特别义务**：一旦机器/人工发现疑似儿童性虐材料，须按目标辖区法律处置（美国须报 NCMEC；多地有强制报告义务）。🔴

### 3.3 违法/有害内容处置时效 🔴

| 内容类别 | 处置时效（建议 SLA） | 优先级 |
|---|---|---|
| 机器审核高危拦截（CSAM、自残、暴力、诈骗） | **秒级实时拦截，不进入漂流海** | 🔴 |
| 用户举报的冒犯/违规内容 | **24 小时内处置**（对齐 Apple UGC 要求） | 🔴 |
| 起底/隐私泄露（港 PDPO） | 收到通知后尽快移除，建议 24h | 🔴 |
| CSAM 发现 | 立即下架 + 保全证据 + 法定报告 | 🔴 |
| 一般违规 | 48–72 小时 | 🟡 |
| EU DSA（如达 VLOP 门槛） | 透明度报告、通知-行动机制——MVP 体量通常不达 VLOP，但 notice-and-action 基础须有 | 🟡 |

## 4. 陌生人社交特有合规

### 4.1 年龄验证要求 🔴

- 注册第一步即年龄门控（出生日期，非简单勾选「我已满 X 岁」）。
- 命中未成年阈值 → 家长同意分支 + 守护模式（见 2.1）。
- 反规避：限制同设备反复改龄；记录年龄声明日志。
- **美国：硬拦 <13**（除非上 VPC）；**台湾：<18 须法代同意**；**EU：<16 须家长同意**（高水位线策略）。
- 进阶年龄核实（🟢）：可选证件/活体，仅在高风险场景（如解锁更多陌生匹配）触发。

### 4.2 反诈披露 🔴

- 拆封/回信关键节点展示**反诈提示**：警惕索要钱财、投资荐股、转移至外部平台、索要私密照片。
- 联系方式检测（已在 MVP）：拦截信件中外发联系方式/外链引流，降低杀猪盘风险。
- 未成年额外提示：陌生人索要见面、私密信息时强提醒 + 一键举报。

### 4.3 举报与执法配合 🔴

- **举报 + 拉黑 + 隐身 + 申诉**四件套（已在 MVP）——同时是商店硬门槛。
- 举报分类（骚扰/诈骗/未成年风险/起底/CSAM/其他），高危类别加急。
- 执法配合：建立合法数据调取响应流程（保全、最小披露、记录），指定对接人/邮箱。
- 透明：申诉机制保证被误封用户可人工复核。

### 4.4 线下见面风险与平台责任边界 🔴

- 产品定位为「书信慢社交」，**MVP 不提供任何线下见面撮合/定位会面功能**——主动收窄责任面。
- ToS 明确：平台不组织/不背书线下见面，用户自行承担线下风险；提供安全见面建议（公共场所、告知亲友）。
- **未成年守护模式：完全禁用任何线下见面引导**，并对涉及约见面的信件内容加强审核。
- 地理仅用于匹配速度（GeoHash5 ±2.4km），不向对方暴露精确位置——已是良好实践，文档化。

## 6. 本地化方案

### 6.1 语言优先级建议

| 优先级 | 语言 | 市场 | 阶段 |
|---|---|---|---|
| P0 🔴 | 繁体中文（台湾用语） | 台湾 | MVP |
| P0 🔴 | 繁体中文（香港用语） | 香港、澳门 | MVP |
| P0 🔴 | 英文 | 法律文本兜底 + 欧美/星马 | MVP |
| P1 🟡 | 简体中文 | 星马华语、海外华人 | MVP/紧随 |
| P2 🟢 | 日/韩/其他欧语 | 区域扩张 | 演进 |

> 港台繁体并非同一套用语（如「網絡 vs 網路」「質素 vs 品質」），文案与法律文本须分别本地化，不可共用一份繁体。法律文件（隐私政策/ToS）以**英文为权威兜底版本**，各语言版本注明「以英文版为准」可降低翻译歧义风险（但港台监管要求当地语言可读，故仍须提供中文）。

### 6.2 多语种内容审核 🔴

- 审核模型须覆盖繁中、简中、英文（含粤语口语、网络黑话、谐音绕过）。
- 联系方式/引流检测须适配各地格式（手机号、各地社交平台 ID、谐音变体）。
- 敏感词/违禁内容词库分辖区维护（如香港「起底」相关、政治敏感度差异）。
- 高危类别（CSAM、自残）须语言无关的强召回，宁可误报转人工。

### 6.3 地区文化适配 🟡

- 「漂流邮局/车马/信鸽」世界观跨文化普适性好，保留；地名/距离展示按当地习惯（公里制）。
- MBTI 自报在港台/欧美接受度高，文案可直接用；「荣格互补」等术语提供通俗解释。
- 节庆/问候本地化（春节 vs 圣诞）；颜色与意象避免地区禁忌。
- 反诈/安全提示按当地高发诈骗类型定制（台湾「假交友真投资」、香港「网恋杀猪盘」话术）。
- 客服与申诉支持至少覆盖中英文工作时间响应。

## 7. MVP vs 可延后 总览

**MVP 必须（🔴）**：年龄门控 + 未成年家长同意（邮箱级）+ 守护模式 + 机器审核秒级拦高危 + 举报/拉黑/隐身/申诉 + 24h 处置 SLA + CSAM 处置 + DPIA + 隐私政策/ToS（中英繁简，含未成年专章与境外 AI 披露）+ 同意管理 + 删除/可携（人工级）+ 数据最小化落地 + 境外模型出境评估/SCC/zero-retention/PII 掩码 + AI 内容标识 + 商店合规填报 + 数据最小化卖点文档化。

**可延后（🟢）**：进阶年龄核实（证件/活体）、COPPA 级 VPC（除非进 <13 美国市场）、区域化模型端点、自助数据导出按钮、DSA VLOP 级义务、第三/四梯队语言、CCPA 其他州扩展。

**战略两条红线**：
1. **美国 <13**：MVP 直接硬拦 <13 以规避 COPPA VPC，否则成本/风险极高。
2. **境外审核出境**：无 zero-retention 不上未成年内容；出境必先 PII 掩码。
