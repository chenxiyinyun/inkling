## 0. 核心原则：省的是「云服务器的钱」，不是「测试」

团队决策：**因服务器成本，暂不租云做真机部署测试。**

关键区分——**真机部署（云，花钱） ≠ 联调测试（本机，免费）**。绝大部分开发与验证不碰云。所有工作按"要不要花钱"分三档：

| 档 | 含义 | 成本 | 覆盖范围 |
|---|---|---|---|
| **A 零基建** | 连数据库都不用 | 0 | 单元测试、前端 Mock 全流程、修 bug、重构、CI |
| **B 本机 Docker** | 自己电脑 `docker compose up` 起 PG+Redis | 0 | 后端端到端联调、集成测试、状态机验证 |
| **C 需云/付费** | 必须有公网/HTTPS/第三方服务 | 花钱 | 生产部署、第三方审核 API、Web Push、eKYC —— **推迟** |

前两档全程零成本，足以把 MVP 做到"能联调、能回归、核心循环被验证"。

## 4. 测试基建落地方案（全程不需云）

- **运行器**：统一用 **Vitest**（ESM+TS+pnpm 单仓友好，避开 Jest 的 ts-jest/ESM 摩擦；Nuxt 生态原生支持）。根加 `"test":"pnpm -r test"`，各包加 `"test":"vitest run"`。
- **Service 单测**：service 全是构造器注入纯类，测试里直接 `new XxxService(mockPrisma, mockRedis, ...)`，无需 `@nestjs/testing`。
- **集成测试（B 档，本机/CI Docker）**：复用仓库已有的 [docker-compose.yml](../docker-compose.yml)（PG16+Redis7）。**重点是纯 mock 测不出的并发/原子语义**：N 人抢同一封信只 1 成功、配额原子扣减不成负、拆封唯一性、Redis 锁只删自己的 token。
  - `testcontainers-node` 可选（CI 隔离用）；**`pg-mem` 放弃**——不支持本项目依赖的 `updateMany` 原子语义/迁移。
- **e2e**：`@nestjs/testing` + `supertest`，`Test.createTestingModule({imports:[AppModule]})` → `app.init()`。⚠️ e2e setup 要复刻 [main.ts](../apps/api/src/main.ts) 的全局管线（ValidationPipe / TransformInterceptor / AllExceptionsFilter），否则响应体/校验行为与真机不一致——**建议把 bootstrap 配置抽成可复用函数**。用独立测试库名 `inkling_test`。
- **scheduler 验证**：直接调度方法（不靠 cron 真等）+ 伪造过期时间数据，断言状态机迁移；用秒级 env（如 `POOL_DELAY=2s`）驱动。
- **前端测试**：`@nuxt/test-utils` + Vitest + `@vue/test-utils` + happy-dom，先测 store/composable。
- **CI（免费，不需自购服务器）**：`.github/workflows/ci.yml`，`ubuntu-latest` 用 `services:` 声明 postgres:16 + redis:7（GitHub Actions 免费额度内）。流水线：install → build:shared → typecheck → vitest → `prisma migrate deploy` → 集成/e2e。把"不租云也能端到端验证"固化为每次 push 自动跑。

## 6. 本机验证注意事项（避免被假象误导）

- **OCEAN_EMPTY 假象**：`FishingRecord @@unique([userId,letterId])` 使"一个人打捞过的信即便回池也永远捞不到"。早期 seed 数据少时海面会很快空，容易误判功能坏掉——**本机验证前把种子信铺足量**。
- **配额重置时区**：`today()` 用 UTC 自然日，对 UTC+8 用户配额在北京时间早 8:00 重置而非午夜，慢社交"每日潮汐"体验会偏移。MVP 可先文档说明 UTC，或后续按用户时区（P2）。
- **环境前置**：pnpm v10 需 `onlyBuiltDependencies`（已配）；本环境对 npm/Prisma 引擎下载偶发 ECONNRESET，重试可过。
